# Shield

Shield는 Windows 환경을 위한 파일·폴더 암호화 프로그램입니다. 파일을 압축한 뒤 XChaCha20-Poly1305로 암호화해 `.shd` 컨테이너에 저장하며, 별도의 파일 관리자에서 컨테이너 내부 항목을 탐색하고 선택적으로 추출하거나 새 파일을 추가할 수 있습니다.

현재 문서는 **Shield 2.1.0**을 기준으로 작성되었습니다.

## 주요 기능

- **인증된 파일 암호화**: XChaCha20-Poly1305를 사용해 데이터 청크, 메타데이터, 키 슬롯 및 임시 데이터를 인증·암호화합니다.
- **비밀번호 기반 키 유도**: Argon2id v1.3을 사용합니다. 기본 설정은 메모리 256 MiB, 병렬도 4, 반복 횟수 15회입니다.
- **키 파일 지원**: 비밀번호와 키 파일을 함께 사용하거나, 설정에 따라 키 파일만 사용할 수 있습니다. 키 파일은 SHA3-512 지문으로 처리합니다.
- **KEK/DEK 키 구조**: 파일 데이터 키(DEK)를 키 암호화 키(KEK)로 보호합니다. 두 개의 키 슬롯을 사용하며 비밀번호 변경과 전체 데이터 키 교체를 별도 작업으로 제공합니다.
- **청크 단위 처리**: 데이터를 64 KiB 단위로 처리하고 각 청크에 인증 태그를 적용합니다.
- **압축 선택**: LZMA2, Zstandard 또는 무압축 저장을 지원합니다. 자동 모드는 입력 크기와 압축 특성 등을 고려해 방식을 선택합니다.
- **크기 정보 일부 완화**: 암호화 데이터 뒤에 무작위 길이의 패딩을 추가합니다. 원본 크기를 완전히 숨기는 기능은 아닙니다.
- **파일 무결성 검증**: SHA3-512를 이용해 암호화 후 복원 검증을 수행합니다.
- **파일 관리자**: `.shd` 컨테이너를 열어 내부 항목을 탐색하고, 전체 또는 선택 항목을 추출하거나 파일·폴더를 추가 및 삭제할 수 있습니다.
- **보호된 임시 작업 공간**: 임시 데이터는 별도 암호화 저장소 또는 사용자 전용 스테이징 경로를 사용합니다.
- **키 및 비밀번호 관리**: 비밀번호 변경, 전체 키 교체, 키 파일 생성 기능을 제공합니다.
- **마우스 엔트로피 보조 수집**: 운영체제 난수와 함께 마우스 입력에서 얻은 데이터를 프로그램 전체의 난수 생성에 보조적으로 섞습니다. 수집은 표시 목적으로만 진행되며 암호화나 키 생성이 수집 완료를 기다리지는 않습니다.
- **화면 캡처 방지**: 기본적으로 화면 캡처 방지 기능을 활성화합니다. 설정 파일이 손상된 경우에도 보호 기능이 꺼지지 않도록 처리합니다.
- **동시 작업 보호**: 컨테이너별 프로세스 간 잠금을 사용해 읽기와 쓰기 작업의 충돌을 방지합니다.
- **임시 작업 복구**: 비정상 종료 후 남은 임시 작업 폴더와 손상된 작업 기록을 검사하고 복구할 수 있도록 지원합니다.
- **Windows 셸 통합**: 설치 시 파일·폴더 암호화, `.shd` 복호화 및 SHIELD에서 열기 메뉴를 등록합니다.
- **설정 관리**: 일반, 보안, 암호화, 파일 관리자 설정을 분류해 관리하고 초기화할 수 있습니다.
- **한국어·영어 지원**: 시스템 언어에 따라 프로그램 표시 언어를 선택합니다.
- **다크 모드**: 밝게, 어둡게, 시스템 따름을 지원합니다.

## 암호화 구성

| 항목 | 사용 기술 및 기본값 |
|---|---|
| 데이터 암호화 | XChaCha20-Poly1305 |
| 인증 태그 | Poly1305, 128비트 |
| 키 길이 | 256비트 |
| nonce | XChaCha20 192비트 nonce 구성 |
| 키 유도 함수 | Argon2id v1.3 |
| Argon2id 메모리 | 256 MiB |
| Argon2id 병렬도 | 4 |
| Argon2id 반복 | 3 + PIM, 기본 PIM 12 (총 15회) |
| 해시 및 파일 검증 | SHA3-512 |
| 키 등급 난수 추출 | SHAKE256 및 운영체제 난수 |
| 압축 | LZMA2, Zstandard, 무압축 |
| 데이터 청크 | 64 KiB |

비밀번호는 입력 경계에서 Unicode NFC로 정규화됩니다. PIM은 키 유도 반복 횟수에 반영되며 컨테이너에 저장되지 않으므로, 기본값에서 변경했다면 사용자가 별도로 보관해야 합니다.

마우스 엔트로피는 운영체제 난수의 보조 입력입니다. 수집량 표시가 100%에 도달했다고 해서 암호학적 난수의 품질이나 암호화 강도가 수학적으로 보장되는 것은 아닙니다.

## 실행 파일과 창

설치 후 다음 두 창을 사용할 수 있습니다.

- **Shield**: 암호화, 복호화, 비밀번호·키 교체, 디스크 정리, 알고리즘 정보, 설정 및 사용법
- **Shield 파일 관리자**: 폴더 탐색, `.shd` 컨테이너 열기, 전체·선택 추출, 파일·폴더 추가 및 삭제, 본문 검사

동일한 실행 파일에서 다음 인수를 사용할 수 있습니다.

```text
shield.exe                       암호화 창
shield.exe --manager [경로]      파일 관리자 창
shield.exe --open <파일.shd>     지정한 컨테이너를 열 파일 관리자 창
shield.exe --encrypt <경로>      대상 경로가 선택된 암호화 창
shield.exe --decrypt <파일.shd>  복호화 탭이 열린 암호화 창
```

### 창 크기 및 배치

- 기본 창 크기: 1040×700
- 최소 창 크기: 800×560
- 가로 공간이 760px 이상이면 두 열 배치를 사용합니다.
- 고급 옵션은 기본적으로 접혀 있습니다.
- 상단 탭과 하단 실행 버튼·상태 표시줄은 고정되며 가운데 영역만 스크롤됩니다.

## 사용법

### 1. Shield 실행 및 설정

설치 후 시작 메뉴 또는 설치 폴더에서 **Shield**를 실행합니다.

기본 창에는 다음 탭이 있습니다.

- **암호화**: 파일·폴더를 `.shd` 컨테이너로 만듭니다.
- **복호화**: 기존 `.shd` 컨테이너의 내용을 원래 파일·폴더로 복원합니다.
- **비밀번호·키 교체**: 컨테이너의 비밀번호를 변경하거나 데이터 키를 새로 생성합니다.
- **디스크 정리**: 드라이브의 TRIM 또는 여유 공간 정리를 실행합니다.
- **알고리즘·정보**: 사용 알고리즘과 현재 PC에 적용된 보호 상태를 확인합니다.
- **설정**: 일반, 보안, 암호화, 파일 관리자 설정을 관리합니다.
- **사용법**: 프로그램 안에서 각 창의 간단한 안내를 확인합니다.

설정 탭에서는 다음 기능을 사용할 수 있습니다.

- 일반: 프로그램의 기본 동작 설정
- 보안: 마우스 엔트로피 및 화면 보호 관련 설정
- 암호화: 암호화 관련 설정
- 파일 관리자: 파일 관리자 관련 설정
- 분류별 설정 초기화
- 전체 설정 초기화
- 설정 파일 삭제

설정 파일은 임시 파일에 기록한 뒤 이름을 바꾸는 방식으로 저장합니다. 비밀번호, 키, 키 파일 경로 및 컨테이너 경로는 설정에 저장하지 않습니다.

기본 창 오른쪽의 **파일 관리자** 버튼을 누르면 별도 파일 탐색 창이 열립니다. 파일이나 폴더를 Shield 창으로 끌어다 놓아 대상 경로를 지정할 수도 있습니다.

### 2. 파일·폴더 암호화

1. **암호화** 탭에서 **파일 선택…** 또는 **폴더 선택…**을 누릅니다. 또는 대상 파일·폴더를 창으로 끌어다 놓습니다.
2. 비밀번호를 입력하고 확인란에 같은 비밀번호를 다시 입력합니다. 화면의 비밀번호 강도 표시는 참고용 추정치입니다.
3. **PIM**은 기본적으로 `12`를 사용합니다. 직접 지정할 수도 있지만, PIM은 컨테이너에 저장되지 않으므로 변경한 값은 반드시 별도로 기록해야 합니다.
4. 키 파일을 추가하려면 **키 파일 추가…**를 누릅니다. 새 키 파일을 만들려면 생성 크기를 지정하고 창에 표시되는 무작위성 수집을 마친 다음 **새 키 파일 생성…**을 누릅니다. 생성한 키 파일은 수정하거나 다시 저장하지 말고 별도로 백업하세요.
5. **압축** 방식을 선택합니다.
   - **자동**: 대상 크기와 PC의 메모리·CPU 상황 등을 고려해 방식을 선택합니다.
   - **빠름**: Zstandard를 사용해 처리 속도를 우선합니다.
   - **균형**: LZMA2 중간 설정으로 속도와 압축률의 균형을 맞춥니다.
   - **최대**: LZMA2 높은 압축 설정을 사용합니다. 시간이 오래 걸리고 메모리를 더 많이 사용할 수 있습니다.
6. **저장 위치 직접 선택**을 켜면 `.shd` 파일을 저장할 위치를 지정할 수 있습니다. 끄면 원본 파일·폴더 옆에 `이름.shd`로 저장합니다. 같은 이름이 이미 있으면 다른 번호가 붙습니다.
7. **암호화 시작**을 누릅니다. 대상 확인, 압축, 암호화, 복원 검증 순서로 진행됩니다. 작업 중에는 창을 닫지 말고 완료 메시지와 생성된 `.shd` 파일을 확인하세요.

기본 설정에서는 원본 파일·폴더가 그대로 남습니다. **암호화·복원 검증이 끝나면 원본 파쇄** 옵션을 선택하면 원본 삭제 단계가 추가됩니다.

파쇄는 되돌릴 수 없으므로 먼저 복사본으로 암호화와 복호화를 시험하고, 생성된 컨테이너가 정상적으로 열리는지 확인한 뒤 사용하세요. SSD·USB 플래시 저장장치·스냅샷·클라우드 동기화 폴더에서는 덮어쓰기나 TRIM이 물리적 데이터 삭제를 보장하지 않습니다.

비밀번호 없이 키 파일만 사용하려면 해당 확인란을 명시적으로 선택해야 합니다. 이 경우 키 파일을 가진 사람은 컨테이너를 열 수 있으므로 일반적으로 비밀번호와 키 파일을 함께 사용하는 편이 안전합니다.

#### 마우스 엔트로피 표시

암호화 탭과 비밀번호·키 교체 탭의 오른쪽 영역에 마우스 엔트로피 수집 상태가 표시됩니다.

- 진행률 막대와 백분율을 확인할 수 있습니다.
- 모은 샘플 수는 막대 아래에 항상 표시됩니다.
- 수집이 진행되는 동안에는 마우스 움직임 안내가 함께 표시됩니다.
- 100%에 도달하면 안내 문구는 사라지고 샘플 수만 남습니다.
- 100% 도달 시 진행률 막대는 초록색으로 바뀝니다.

이 기능은 수집 상태를 보여 주는 보조 기능입니다. 암호화 시작이나 키 생성은 마우스 입력을 기다리지 않습니다.

### 3. `.shd` 파일 복호화

1. **복호화** 탭에서 **.shd 파일 선택…**을 누르고 복호화할 컨테이너를 선택합니다. `.shd` 파일을 창에 끌어다 놓아도 됩니다.
2. 암호화할 때 사용한 비밀번호를 입력합니다.
3. 암호화할 때 PIM을 기본값에서 변경했다면 동일한 PIM을 지정합니다. PIM이 다르면 올바른 비밀번호를 입력해도 열리지 않습니다.
4. 암호화할 때 키 파일을 사용했다면 당시 사용한 키 파일을 모두 추가합니다. 여러 키 파일은 순서와 관계없이 등록할 수 있지만 하나라도 빠지거나 내용이 바뀌면 복호화할 수 없습니다.
5. 필요하면 **저장 폴더 직접 선택**을 켜서 결과 폴더를 지정합니다. 끄면 `.shd` 파일과 같은 폴더에 복원합니다.
6. **복호화 시작**을 누릅니다. 기존 파일을 덮어쓰지 않으며 같은 이름이 있으면 복원 파일 이름에 `(decrypted)`가 붙습니다.

Shield는 본문을 인증한 뒤 압축을 해제합니다. 비밀번호·PIM·키 파일을 잃어버리거나 잘못 입력한 경우에는 복호화할 수 없습니다.

### 4. 파일 관리자에서 컨테이너 탐색하기

1. 기본 창의 **파일 관리자** 버튼을 누릅니다.
2. 주소 입력란에 폴더 경로를 입력하고 Enter를 누르거나 목록에서 폴더를 두 번 클릭해 이동합니다. **위로**는 상위 폴더로, **드라이브**는 드라이브 목록으로 이동합니다.
3. `.shd` 파일을 두 번 클릭하거나 창으로 끌어다 놓습니다. Windows 탐색기의 **SHIELD에서 열기** 메뉴로 열 수도 있습니다.
4. 컨테이너 비밀번호, 암호화 당시의 PIM, 사용한 키 파일을 입력하고 **열기**를 누릅니다.
5. 열리면 **파일** 탭에서 내부 폴더를 두 번 클릭해 탐색합니다. **정보** 탭에서는 컨테이너 형식, 알고리즘, 압축 방식, 크기와 파일 수 등을 확인할 수 있습니다.

컨테이너를 여는 동작은 키 슬롯·메타데이터와 7z 목록을 확인하는 단계이며 본문 전체를 검사한 것은 아닙니다. 본문 전체의 청크 인증을 확인하려면 **본문 전체 검사**를 누르세요.

컨테이너를 연 직후 비밀번호와 키를 메모리에 계속 보관하지 않습니다. 목록을 읽은 뒤 자격 증명을 지우며, 검사·추출·추가·삭제 작업을 수행할 때마다 다시 입력해야 합니다.

### 5. 전체 또는 일부 항목 추출

- **선택 항목 추출…**: 목록에서 원하는 파일·폴더를 클릭해 선택합니다. `Ctrl`을 누른 채 클릭하면 여러 항목을 선택할 수 있습니다. 버튼을 누르고 추출할 폴더를 지정합니다.
- **전체 추출…**: 컨테이너의 모든 파일·폴더를 지정한 폴더에 복원합니다.

추출 작업은 자격 증명을 다시 입력해야 진행할 수 있습니다. 선택 추출이 중간에 실패하면 이미 이동한 항목까지 되돌리는 처리가 적용됩니다.

추출 후에는 파일과 폴더가 의도한 위치에 생성되었는지 확인하세요. 중요한 자료라면 추출 결과를 열어 내용까지 확인한 다음 원본 컨테이너를 별도로 보관하는 것이 좋습니다.

### 6. 열린 컨테이너에 파일·폴더 추가 및 삭제

#### 파일·폴더 추가

1. 파일 관리자에서 컨테이너를 연 뒤 파일을 넣을 내부 폴더로 이동합니다. 현재 보고 있는 폴더가 추가 위치가 됩니다.
2. **파일 추가…** 또는 **폴더 추가…**를 누릅니다. 파일·폴더를 현재 파일 관리자 창으로 끌어다 놓아 추가할 수도 있습니다.
3. 추가 시 사용할 압축 방식을 선택합니다.
4. 기존 항목과 이름이 충돌하면 표시되는 확인 창에서 덮어쓰기 여부를 결정합니다.
5. 추가 작업은 기존 내용을 다시 구성하고 새 키로 전체 컨테이너를 재암호화한 뒤 검증합니다. 따라서 컨테이너가 클수록 시간이 걸리고 임시 작업을 위한 여유 공간이 필요할 수 있습니다.

**추가·검증 후 추가한 원본 파쇄** 옵션은 추가된 원본 파일을 삭제하는 작업을 동반합니다. 기본적으로 끄고 사용하는 것을 권장하며 활성화하기 전에 대상과 백업을 확인하세요.

#### 항목 삭제

파일 관리자에서 지원하는 선택 항목 삭제 기능을 사용하면 컨테이너 내부의 파일·폴더를 제거할 수 있습니다.

삭제 작업은 컨테이너 내용을 다시 구성하고 전체를 재암호화·검증한 뒤 교체합니다. 설정에서 삭제 전 확인을 사용할 수 있으며, 삭제 작업 전에는 별도 백업을 권장합니다.

### 7. 비밀번호 변경 및 전체 키 교체

1. 기본 창의 **비밀번호·키 교체** 탭으로 이동합니다.
2. 대상 `.shd` 파일을 선택하고 현재 비밀번호, 현재 PIM, 기존 키 파일을 입력합니다.
3. 변경 방식을 선택합니다.
   - **비밀번호만 변경 (빠름)**: 파일 데이터 키(DEK)를 새 자격 증명으로 다시 보호합니다. 본문 데이터는 다시 암호화하지 않으므로 일반적으로 빠릅니다.
   - **전체 키 교체**: 새 DEK를 만들고 본문 전체를 다시 암호화·검증합니다. 컨테이너 크기에 따라 시간이 오래 걸리고 추가 저장 공간이 필요합니다.
4. 새 비밀번호를 두 번 입력하고 새 PIM을 지정합니다. 새 키 파일을 사용할 경우 **키 파일 추가…** 또는 **새 키 파일 생성…**으로 지정합니다.
5. **비밀번호 변경** 또는 **전체 키 교체**를 눌러 완료될 때까지 기다립니다.

작업 전에 `.shd` 파일을 별도 위치에 백업하세요. 비밀번호나 키를 바꾸더라도 이전에 만들어 둔 백업 파일, 클라우드 버전 기록, 볼륨 섀도 복사본은 자동으로 변경되지 않습니다. 해당 사본은 이전 자격 증명으로 계속 열릴 수 있습니다.

### 8. 디스크 정리

1. **디스크 정리** 탭에서 대상 드라이브를 선택합니다.
2. SSD에서 삭제된 블록 처리를 요청하려면 **TRIM 실행**을 사용합니다. 관리자 권한 확인 창(UAC)이 표시될 수 있으며 HDD에서는 지원되지 않을 수 있습니다.
3. 선택 사항인 **여유 공간 덮어쓰기 시작**은 드라이브의 여유 공간을 `00 → FF → 난수` 순서로 세 번 기록합니다. 매우 오래 걸릴 수 있고 SSD의 쓰기 수명을 소모할 수 있습니다.

디스크 정리 기능은 삭제된 데이터의 물리적 제거를 보장하지 않습니다. SSD의 웨어 레벨링, 컨트롤러 동작, 스냅샷과 백업 등의 영향으로 실제 저장 매체에 남은 데이터까지 제거되었다고 단정할 수 없습니다.

파쇄·여유 공간 덮어쓰기·TRIM 작업이 실패하면 성공으로 표시하지 않고 오류로 알립니다. 이미 생성된 `.shd` 결과 파일은 별도로 유지됩니다.

### 9. Windows 탐색기 우클릭 메뉴

설치하면 Windows 탐색기에서 파일·폴더를 우클릭해 다음 기능을 사용할 수 있습니다.

- **Shield로 암호화**
- `.shd` 파일의 **Shield로 복호화**
- **SHIELD에서 열기**

Windows 11에서는 메뉴가 **더 많은 옵션 표시** 안에 있을 수 있습니다. 메뉴를 사용할 수 없다면 Shield를 직접 실행해 대상을 선택하세요.

### 10. 자동 잠금 및 메모리 보호

- 암호화 창과 파일 관리자에 입력한 비밀번호는 2분 동안 입력이 없으면 자동으로 지워집니다.
- 파일 관리자에서 열린 컨테이너는 5분 동안 조작이 없으면 키와 목록을 메모리에서 지우고 닫습니다.
- 컨테이너를 열어 목록을 읽은 직후 키와 비밀번호를 지웁니다.
- 검사·추출·추가·삭제 작업을 할 때마다 비밀번호와 PIM, 필요한 키 파일을 다시 입력해야 합니다.
- 이번 세션 동안 자격 증명을 계속 기억하는 기능은 제공하지 않습니다.
- 작업 중에는 창을 닫을 수 없습니다. 취소 기능이 표시되면 먼저 작업을 취소하거나 완료한 뒤 종료하세요.

메모리 잠금과 초기화는 최선의 노력입니다. 관리자 권한, 커널 수준 접근 또는 동일 사용자 권한으로 실행되는 악성 프로그램까지 방지하는 것은 아닙니다.

### 11. 동시 작업 잠금 및 임시 파일 복구

컨테이너별로 Windows `LockFileEx` 기반 잠금을 사용합니다.

- 여러 읽기 작업은 동시에 진행할 수 있습니다.
- 쓰기 작업은 단독으로 진행합니다.
- 다른 작업이 사용 중이면 최대 3초 동안 기다린 뒤 오류를 표시합니다.
- 오류가 발생하면 **다시 시도** 버튼을 사용할 수 있습니다.
- 비정상 종료 시 운영체제가 잠금을 해제하므로 잠금이 영구적으로 남는 상황을 방지합니다.

임시 작업 폴더는 생성 전에 기록 파일에 등록합니다. 프로그램이 비정상 종료되어 임시 폴더가 남거나 기록 파일이 손상된 경우에는 복구 검사를 제안합니다.

Shield가 소유한 임시 폴더인지 프로세스 번호와 시작 시각, 경로 등의 정보를 확인한 뒤 정리합니다.

## 보안 및 사용상 주의사항

- **비밀번호, PIM, 키 파일을 안전하게 보관하세요.** 이 중 필요한 자격 증명을 잃으면 컨테이너를 복호화할 수 없습니다.
- 키 파일은 수정하거나 다시 저장하지 마세요. 암호화 데이터와 별도의 안전한 위치에 백업하는 것이 좋습니다.
- PIM을 기본값 12에서 변경했다면 반드시 기록하세요. PIM은 컨테이너에 저장되지 않습니다.
- 원본 파쇄는 되돌릴 수 없습니다. 먼저 복사본으로 암호화와 복호화를 시험하고 생성된 컨테이너가 정상적으로 복원되는지 확인하세요.
- **SSD, USB 플래시 저장장치, 스냅샷, 볼륨 섀도 복사본 및 클라우드 동기화 폴더에서는 덮어쓰기나 TRIM이 물리적 데이터 삭제를 보장하지 않습니다.**
- 비밀번호 변경이나 전체 키 교체를 수행해도 작업 전 만들어진 백업, 클라우드 버전 기록 및 복사본은 이전 자격 증명으로 계속 열릴 수 있습니다.
- 마우스 엔트로피는 운영체제 난수에 추가되는 보조 입력이며 독립적인 난수 생성기나 암호학적 안전성의 보증이 아닙니다.
- 화면 캡처 방지는 운영체제의 화면 캡처 제어 기능에 의존합니다. 모든 캡처·녹화·외부 촬영 수단을 차단하지는 않습니다.
- 메모리 초기화, 메모리 잠금 및 프로세스 보호는 최선의 노력입니다. 같은 사용자 권한으로 실행되는 악성 프로그램, 관리자 권한, 커널 수준 접근 또는 물리적 접근까지 방지하지는 못합니다.
- 암호문 크기와 패딩 정보로 원본 크기의 대략적인 범위를 추정할 수 있습니다. 크기 정보가 완전히 은닉되는 것은 아닙니다.
- 외부 보안 감사는 수행되지 않았습니다. 프로젝트에 포함된 자동 테스트 결과가 독립적인 보안 감사나 모든 환경에서의 안전성을 의미하지는 않습니다.

## 파일 형식 호환성

Shield 2.1.0은 `.shd` v2 형식을 사용합니다. Shield 1.x에서 생성한 `.shd` 파일은 Shield 2.x에서 열 수 없습니다. 1.x 사용자는 업그레이드 전에 기존 컨테이너를 1.x에서 복호화한 뒤 Shield 2.x에서 다시 암호화해야 합니다.

2.0.0과 2.1.0 사이의 호환성은 별도 확인이 필요합니다. 형식 버전은 암호화된 메타데이터 안에 저장되며, 이전 형식과의 하위 호환을 제공하지 않는다는 개발 기록을 참고하세요.

## 빌드

### 요구 사항

- Windows 10 또는 Windows 11 (x64)
- Rust stable 1.80 이상 권장
- Visual Studio C++ Build Tools 및 Windows SDK (`rc.exe` 포함)
- .NET SDK 6 이상
- 최초 의존성 복원을 위한 인터넷 연결
- 선택 사항: GnuPG 또는 Gpg4win (배포 파일 GPG 서명 시)
- 선택 사항: UPX (포터블 실행 파일 생성 시)

WiX 5.0.2는 프로젝트의 로컬 .NET 도구 설정을 통해 복원됩니다.

### 빌드 명령

PowerShell에서 프로젝트 루트 디렉터리를 열고 실행합니다.

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\build.ps1
```

기본 실행은 GPG 서명 여부와 UPX 경로를 묻습니다.

서명하지 않고 빌드하려면 다음 명령을 사용합니다.

```powershell
.\build.ps1 -NoSign
```

GPG 서명을 비대화형으로 진행하려면 공개키 파일을 지정합니다.

```powershell
.\build.ps1 -Sign -PublicKeyPath .\public-key.asc
```

비밀키가 기본 GPG 키링이 아닌 별도 키링에 있는 경우에는 키링 경로도 지정할 수 있습니다.

```powershell
.\build.ps1 -Sign -PublicKeyPath .\public-key.asc -GpgHome D:\keys\gnupg
```

### UPX 포터블 빌드

UPX를 사용하면 설치 프로그램과 별도로 포터블 실행 파일을 생성할 수 있습니다.

기본 빌드 중 표시되는 UPX 경로 입력란에 `upx.exe` 경로 또는 `upx.exe`가 들어 있는 폴더 경로를 입력합니다.

명령행에서 직접 지정할 수도 있습니다.

```powershell
.\build.ps1 -UpxPath "C:\Tools\UPX\upx.exe"
```

UPX를 사용하지 않으려면 다음과 같이 실행합니다.

```powershell
.\build.ps1 -NoUpx
```

UPX 압축 이후에는 `upx -t` 무결성 검사와 ASLR/DEP 플래그 확인을 수행합니다.

포터블 버전은 다음 이름으로 생성됩니다.

```text
Shield_v{버전}_portable.exe
```

포터블 실행 파일은 설정을 실행 파일 옆의 `Shield_data` 폴더에 저장합니다.

UPX는 별도로 설치해야 합니다. UPX가 없는 경우 포터블 실행 파일은 생성되지 않습니다.

### 빌드 산출물

빌드가 완료되면 `dist\`에 배포 파일이 생성됩니다.

- `Shield.msi`: Windows 설치 프로그램
- `Shield_Project_v2.1.0.zip`: 소스 배포 ZIP
- `SHA256SUMS.txt`: 배포 파일의 SHA-256 체크섬
- `Shield_v{버전}_portable.exe`: UPX를 사용한 포터블 실행 파일 (선택 사항)
- 서명 사용 시 `.sig` 분리 서명, 공개키 파일 및 `VERIFY.txt`

빌드 스크립트는 릴리스 빌드, 자동 테스트, WiX 도구 복원, MSI 생성을 차례로 수행합니다. 단계 중 하나라도 실패하면 이후 단계로 진행하지 않습니다.

서명 단계에서는 지정한 공개키를 임시 키링에서 검사하고 생성된 서명을 검증합니다. 서명이 필요한 배포에서는 함께 제공된 `VERIFY.txt`의 지문과 검증 절차를 확인하세요.

## 테스트

2.1.0 개발 기록에 따르면 다음 테스트 결과가 보고되었습니다.

- `cargo build`: 성공, 경고 0개
- `cargo test`: 104개 테스트 통과
- `cargo clippy --all-targets`: 경고 0개
- 이후 추가 수정 단계에서 `cargo test` 105개 통과 결과 보고

다만 105개 테스트 통과 결과는 기본 창 크기 변경 및 마우스 엔트로피 표시 변경 이전의 결과입니다. 해당 변경 이후에는 재빌드와 재테스트가 완료되지 않았으므로 최종 배포 시 다시 확인해야 합니다.

주요 테스트 범위는 다음과 같습니다.

- 파일·폴더 암호화 및 복호화 왕복
- 인증 및 변조 검출
- 컨테이너 잘림 및 데이터 덧붙임
- 비밀번호 변경 및 전체 키 교체
- 경로 검증 및 경로 공격 방지
- 압축 항목 제한 및 압축률 검사
- 임시 저장소 무결성
- 컨테이너 선택 추출 및 파일 추가·삭제
- 동시 읽기·쓰기 잠금
- 임시 작업 기록과 복구 처리
- 숨은 스트림(ADS) 및 다운로드 표시(MOTW)
- 키 파일 권한 및 비밀번호 길이 제한
- 화면 캡처 방지 관련 테스트
- 설정 저장 및 초기화
- 한국어·영어 문자열과 글리프 검사
- 마우스 엔트로피 관련 테스트

자동 테스트는 GUI의 모든 수동 동작, 실제 설치·업그레이드 환경, 전원 차단 상황, 대용량 실사용 환경, 다른 프로세스의 메모리 접근 또는 SSD의 물리적 삭제 여부를 검증하지 않습니다.

### 아직 확인되지 않은 항목

개발 기록에서 다음 항목은 실제 환경 검증이 완료되지 않았습니다.

- UPX 포터블 빌드의 실제 압축 실행
- 서로 다른 프로세스가 비정상 종료했을 때 잠금이 해제되는지 여부
- 실제 창에서 화면 캡처 방지가 적용되는지 여부
- 125%, 150%, 200% 화면 배율에서의 배치
- 다크 모드의 제목 표시줄
- MSI 우클릭 메뉴의 영어 표시
- FAT32 및 NTFS가 아닌 드라이브에서의 동작
- GUI 버튼을 직접 눌러 보는 수동 확인
- 기본 창 크기 및 마우스 엔트로피 UI 변경 이후의 재빌드·재테스트

## 배포 파일

사용자는 프로젝트의 **GitHub Releases**에서 사전 빌드된 `Shield_2.1.0.msi`를 내려받을 수 있습니다. 소스에서 직접 빌드하려는 경우 저장소의 소스를 내려받아 위 빌드 절차를 따르세요.

배포 파일을 받은 경우 가능하면 SHA-256 체크섬과 GPG 서명을 확인한 뒤 설치하는 것을 권장합니다.
