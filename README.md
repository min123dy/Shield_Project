SHIELD 1.1 - 프로젝트 설명 및 소스 연결 검토
============================================

1. 검토 범위와 한계
-------------------
이 프로젝트 폴더에는 다음 파일이 포함되어 있습니다.
- Cargo.toml, build.rs, build.ps1, installer.wxs, installer.ko-KR.wxl
- src/ 아래의 Rust 모듈 (아래 2절)
- docs/ 아래의 프로젝트 설명, 빌드 방법, 사용자 안내

이 문서는 소스 코드를 정적으로 살펴본 설명입니다. 여기서 컴파일, MSI 생성,
실제 암복호화, 운영체제별 보안 동작이 성공했다고 인증하는 것은 아닙니다.

2. Rust 모듈 구성
-----------------
main.rs      앱 상태, 입력 검증, 작업 스레드 시작/완료 처리, 창 아이콘/크기 설정
ui.rs        화면 배치(탭, 탐색기, 진행 표시줄), 비밀번호 칸 등 공용 위젯
views.rs     탭별 화면(암호화/복호화/비밀번호 변경/디스크 정리/도움말)
help.rs      앱 안의 사용법·주의사항 문구
engine.rs    키 유도(Argon2id), 키 봉인, 스트리밍 AEAD, 비밀번호 변경, 암호화/복호화 흐름
keyfile.rs   키 파일 결합/생성
archive.rs   7z(LZMA2) 압축/해제, 진행률, 압축 항목 경로 검증
wipe.rs      원본 파쇄, 디스크 종류 판별, TRIM, 여유 공간 덮어쓰기
entropy.rs   OS 난수 + 마우스 엔트로피 풀, 보수적 엔트로피 계산
progress.rs  작업 단계/진행률/취소 상태 공유
sectemp.rs   암호화된 임시 파일(Read/Write/Seek)
harden.rs    메모리 잠금, 프로세스 DACL, SecretBuf
icon.rs      절차적으로 그린 아이콘 (build.rs가 exe 리소스로 넣고, 창 아이콘으로도 사용)

4. 암호화 구성 개요
-------------------
엔진은 파일별 32바이트 DEK를 만들고, Argon2id로 유도한 키로 해당 DEK를 봉인합니다.
데이터와 메타데이터는 ChaCha20-Poly1305로 인증 암호화됩니다.

소스의 기본 Argon2id 파라미터는 메모리 128 MiB, 반복 횟수 3+PIM, 병렬도 2입니다.
PIM 범위는 0~64이고 새 파일의 기본값은 12입니다(1.0의 기본값 0으로 만든 파일은 자동 재시도로 열림). 파일 데이터 처리는 64 KiB 단위로 스트리밍됩니다.
압축에는 7z 라이브러리를 사용하며, 임시 압축 데이터는 SecTemp를 거칩니다.

고정 매직 바이트가 없는 파일 형식으로 작성되어 있지만, 이것이 암호화 여부를 숨기거나
난수와 구별 불가능하다는 보장은 아닙니다. 히든 볼륨/부인 가능 저장 기능은 없습니다.

5. GUI 및 파일 탐색기 통합
--------------------------
main.rs는 실제 GUI 진입점입니다. 암호화/복호화 우클릭 메뉴는 MSI에서 등록되며,
선택한 파일/폴더를 --encrypt 또는 --decrypt 인수로 프로그램에 전달합니다.
현재 main.rs의 동작은 항목을 선택한 상태로 GUI를 여는 것입니다. 우클릭 즉시
암호화/복호화를 실행하는 방식은 아닙니다. 사용자가 자격 증명을 입력한 뒤 버튼을 눌러야 합니다.

WiX 설치 파일은 사용자 설명서를 설치 폴더에 배치하고 시작 메뉴에 바로가기를 생성하도록
설정되어 있습니다. 프로젝트의 docs/03_사용_방법.txt가 MSI에 포함되는 원본 문서입니다.

6. 1.1에서 수정한 보안/안정성 항목
-----------------------------------
- 폴더 복호화 불가: 1.0은 sevenz_rust::compress가 만든 빈 이름의 루트 항목을 검증에서 거부해
  폴더 .shd를 풀 수 없었습니다. 자체 압축기로 교체했고 1.0 형식도 열 수 있게 했습니다(회귀 테스트 포함).
- 프로세스 DACL: 소유자에게 암묵적으로 남던 WRITE_DAC 때문에 같은 사용자 프로그램이 DACL을 바꿔
  보호를 우회할 수 있었습니다. OWNER RIGHTS ACE로 소유자 권한을 조회/동기화로 제한했습니다.
  이 덕분에 탐색기가 실행 파일 경로를 조회할 수 있어 작업 표시줄 고정도 가능해졌습니다.
- 보안 설명자 메모리 해제(LocalFree) 누락 수정.
- 비밀번호 변경: 새 슬롯에서 꺼낸 DEK가 기존 DEK와 같은지 상수 시간 비교로 확인한 뒤에만 기존 슬롯 파기.
- 기본 PIM 0 → 12, 기본값보다 낮은 PIM은 키 파일 없이 쓸 때 비밀번호 20자 이상 요구.
- 압축 항목 검증 강화: 경로의 모든 구성 요소에 대해 장치 이름(CON, NUL, COM1…), 제어 문자,
  끝 공백/마침표, 대체 데이터 스트림(:) 거부. 추출 시 create_new로만 파일 생성(덮어쓰기/링크 추적 없음).
- 외부 명령(cipher, powershell)을 System32 절대 경로로 실행하고 PowerShell 인수는 -EncodedCommand 사용.
- 검증 실패 시 손상된 결과 파일 삭제, 읽기 전용 파일 파쇄 실패 수정, 작업 중 창 닫기 방지.
- 마우스 엔트로피 계산을 보수적으로 변경(불규칙한 움직임 1회당 최대 1비트, 1024비트 요구).

7. 남아 있는 한계
-----------------
- VirtualLock/mlock 성공 여부를 사용자에게 알리지 않으므로 메모리 잠금은 보장이 아닙니다.
- Argon2 내부 메모리, GUI 라이브러리, 기타 임시 버퍼 전체가 잠긴다고 볼 수 없습니다.
- 관리자/커널/물리적 접근은 막지 못합니다.
- HDD 덮어쓰기, SSD 여유 공간 덮어쓰기, TRIM은 복제본/스냅샷/예비 셀까지 물리적으로
  완전 삭제한다고 보장하지 않습니다.
- 독립적인 외부 보안 감사를 받지 않았습니다.

8. 결론
-------
전달된 main.rs와 엔진/보조 모듈 사이의 참조는 소스 수준에서 연결되어 있으며 GUI 진입점도
포함되어 있습니다. 그러나 실제 빌드 및 실행 검증은 별도입니다. 중요 파일에 사용하기 전
Windows x64에서 컴파일, 테스트, 대용량 파일, 잘못된 자격 증명, 취소/전원 중단,
압축 파일 입력, 설치/제거 및 파일 탐색기 통합을 충분히 검증해야 합니다.
