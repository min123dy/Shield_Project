What the new tests cover
- Entropy: value bounds, no repeated blocks in long outputs, key material never waits for extra sources, no GUI sources
  in console mode, status shows labels only (disabled sources as "off"), equal samples from two sources give different
  pools, health (repetition, stuck and counter-like values rejected, recovery)
- Overwriting: 3/7 patterns, changed files refused, only the new file left after replace, exposure check and TRIM
  failures never fail the job, read-only files. Windows: without rights shadow copies are never reported as "none",
  ReTrim helper argument checks. Linux: TRIM without rights gives a hint or a clear answer
- Updates: strict tags (only vX.Y.Z; 3.0.1, v3.0, v3.0.1-rc1, v03.0.1, V3.0.1, full-width digits ... refused), same /
  older / draft / prerelease ignored, assets pointing elsewhere ignored, strict manifest parsing, any change of signature,
  hash or version fails, package naming
- OpenPGP: fixed real signatures (Ed25519, brainpoolP384r1) verify, subkey signatures, tampered data and other keys
  fail, revoked key refused, garbage input gives errors not panics, file size limits
- Settings password: create, unlock, change, remove, wrong password and growing delay, outside edits reset the
  protected values, reset by deleting the file
- Several items: spool collection (one leader), dedup, bundle naming, decrypt folder of bundled containers
- Format: fixed containers made on Windows and Linux open on both (cross_os_tests)
- CLI: parser (options, values, --, unknown commands), secret input keys (Enter, Esc, Ctrl+C/D/U, Backspace), argument
  passwords refused (setting off / flag missing), exit codes (wrong password 3, bad signature 4), encrypt-list-add-
  remove-decrypt end to end, bundled and separate, keyfile, verify, entropy switches (os can't be disabled, settings
  password needed)
- GUI: every tab and settings category drawn headless without panics, multi-select handling, shred dialog text
- Strings: Korean and English keys match, {} counts match, error code format, every shown character is in the fonts

3. Bugs found and fixed (present in 2.1.0)
------------------------------------------
B1  Leftover temp folders on Linux: 2.1 only knew its own pid and reported staging folders of other running Shield
    processes as leftovers; [Delete now] could remove another task's temp files. -> live owners are checked by their
    start time from /proc/<pid>/stat.
B2  Output naming race on Linux: between "name is free" and rename another process could create the name and be
    overwritten. -> renameat2(RENAME_NOREPLACE); on file systems without it, link+unlink for files and a checked rename
    for folders (a small race remains).
B3  No directory fsync after rename on Linux; the new name could be lost on power failure. -> directory fsync.
B4  The Linux data folder was $HOME/Shield. -> XDG ($XDG_CONFIG_HOME/shield, 0700).
B5  Full rekey, adding and deleting simply unlinked the old container, leaving the old key slots and ciphertext on disk;
    anyone knowing the old password could recover and open it. -> after the swap the old file is overwritten with the
    chosen passes, key areas 7 times.
B6  On Linux the "never remove a temp folder from here" check only looked at the path length (3 characters or less), so
    /usr or /etc were not blocked (the name check still prevented an actual deletion). -> system folder list and /proc,
    /sys, /dev refused.
B7  Available memory on Linux came from _SC_AVPHYS_PAGES (without cache), far too low; big files could get a needlessly
    small dictionary or be refused for decryption. -> MemAvailable from /proc/meminfo.
B8  The Linux Hangul font path did not exist on Debian/Ubuntu (boxes instead of text). -> candidate list per distribution.

4. Problems found and fixed during the 3.0 work
-----------------------------------------------
N1  The console shield.exe treated the TRIM elevation helper argument as an unknown command (TRIM did not run after the
    UAC prompt). -> the helper is handled first in the console too.
N2  The portable exe was offered the MSI as an update (it would install over a non-installed copy). -> portable copies
    only get the release page.
N3  The MIME definition contained magic bytes that do not exist; format v2 has no magic (by design: a file does not
    reveal itself as a Shield file). -> extension (*.shd) only.
N4  In GitHub Actions a step's if can't see that step's env, so signing was always skipped. -> job-level env.
N5  A single .shd passed from Explorer only went to decryption when the file existed. -> decided by extension; a missing
    file is an error.
N6  The CLI tests hung in the TRIM stage waiting for UAC. -> TRIM is off in tests (product behaviour unchanged).
N7  Only signed builds (-Sign) failed in the MSI step (WIX0367: two unversioned .sig files in one component can't get
    an automatic GUID). Unsigned test builds leave that component out, so it went unnoticed. -> one component per
    .sig; a Signed=yes build with placeholder .sig files was checked for ko-KR and en-US.
N8  The Korean MSI notice (RTF) was garbled (e.g. "¡á Shield 3.0.0 ¼³Ä¡ ¾È³»"): code page 949 bytes (\'xx) without a
    font charset were decoded with another code page on PCs whose non-Unicode language isn't Korean. -> every
    non-ASCII character is an RTF Unicode escape (\uN), font \fcharset129. Loaded into RichEdit, the text equals the
    source for ko-KR and en-US, and Hangul still shows with an ANSI font charset.

5. Security re-audit (the §9 items)
-----------------------------------
Races
  - Output files: new names only through create_new / RENAME_NOREPLACE / MoveFileEx without replace.
  - Container changes: inter-process lock (writing exclusive, reading shared). A container that changed while open is not
    replaced (size, times and file ID compared).
  - Collecting several items: only the holder of leader.lck opens a window; list files are created with create_new.
  - Remaining risk: a same-user process changing a file right after a check (TOCTOU) is reduced by pinned handles and
    re-checks but can't be ruled out.
Temp files
  - Plaintext staging in 0700 folders with a journal, encrypted SecTemp (random key, block authentication), update
    downloads in a private folder deleted on failure. Spool lists hold paths only, live in the private data folder (0700)
    and are deleted after reading.
Path traversal
  - Unpacking: .., absolute paths, drive letters, reserved names, NUL and link entries refused; the real path is checked
    again to be inside the target folder.
  - Update file names: only the name fixed by version and OS (Shield_v<V>_x64.msi ...) is looked up, so no name from a
    manifest or release can point outside the private download folder.
Memory residue
  - Passwords, keys, key file fingerprints, the entropy pool and settings password derivatives live in Zeroizing /
    SecretBuf and are wiped. The CLI wipes its argv copies and input buffers. The Ctrl+C / SIGTERM / SIGHUP handler wipes
    the pool after cancelling.
  - Remaining risk: the OS's copy of the command line, egui's internal copies, swap (when mlock fails).
Argument exposure
  - --password and friends are refused by default (setting + --allow-arg-secrets), with a warning every time. --json and
    --quiet output contain names, sizes and counts only. Secrets are never read from environment variables, files or
    stdin pipes (refused when not a terminal).
Update tampering
  - HTTPS with rustls certificate validation, non-https redirects refused, response size limits, strict tags, the signed
    manifest's version must equal the tag and be newer, hash match, installer signature. Any failure deletes and stops.
  - Re-publishing an old signed installer under a new tag: stopped by the manifest version check.
  - Remaining risk: a leaked secret signing subkey can't be defended against (subkey expiry and revocation recommended).
Signature bypass
  - rPGP checks issuer, hash prefix, binding signatures, subkey signing flags and back-signatures. Shield allows only
    binary/text signatures, refuses MD5 / SHA-1 / RIPEMD-160 and revoked subkeys. brainpool uses RustCrypto's verify
    function for the last step only (no hand-written crypto). Tests cover tampering, other keys and revoked keys (weak
    hash refusal is checked by code review only).
TOCTOU (other)
  - Shredding: files whose ID, size or times differ from the fixed list are left alone; overwriting uses the same handle.
  - Updates: the verified file is handed to the installer straight from the private folder. A same-user process could
    still swap it in between (same-user malware is outside the threat model).
Entropy
  - The OS RNG is always the base and its failure stops the task. Extra sources never make a key alone and their values
    are never exported. No /dev/input or global coordinates. The console disables the window sources.
Build and release
  - build.rs checks the repository URL and the public key; an .asc with a secret key stops the build. The source zip
    build stops on a secret key block. The signing passphrase never passes through the scripts. CI secrets are used only
    inside a temporary GNUPGHOME that is deleted.

6. Decisions where the stronger option was chosen
-------------------------------------------------
- The old container is overwritten after rekey, add and delete (2.1 did not): slower, but recovery from disk with the old
  password becomes harder.
- Without a settings password security settings can't be changed (3.0 starts with the defaults). Create one first.
- A broken settings MAC resets the protected values to safe defaults, not to the edited values.
- The default is 7 passes on SSDs too (instead of 2.1's single pass on SSDs; 3 only when the user picks it).
- The console never reads passwords from stdin pipes (avoiding exposure beats scripting convenience).
- Updates never install unsigned releases. A build made without a public key says that it can't install updates.
