SHIELD 3.0.0 - 사용 방법 및 안전 안내
===================================

이 문서는 시작 메뉴의 "Shield 사용 설명서"와 설치 폴더의 "사용 방법.txt"(Linux: /usr/share/doc/shield)로
다시 열 수 있습니다. 두 창 모두 '사용법' 탭에 같은 핵심 내용이 있습니다. English: docs\en\03_usage.txt

0. 설치와 업그레이드
--------------------
- Windows: Shield_v3.0.0_x64.msi. 첫 화면의 주의사항을 읽고 확인란을 선택한 뒤 [설치]. 이전 버전은 자동으로
  업그레이드합니다. 설치 폴더가 PATH에 추가되므로 새 명령 창에서 shield 명령을 쓸 수 있습니다.
- Linux: sudo apt install ./shield_v3.0.0_amd64.deb (앱 메뉴, /usr/bin/shield, 파일 관리자 메뉴, .shd 연결).
  설치 없이: chmod +x Shield_v3.0.0_x86_64.AppImage 후 실행, 또는 콘솔 전용 shield-console_v3.0.0_linux_x64.
- 3.0은 2.x와 같은 파일 형식이라 2.x 컨테이너를 그대로 엽니다. 1.x 형식은 열지 않습니다.
- 받은 파일은 먼저 검증하세요: gpg --verify <파일>.sig <파일>, 또는 이미 설치된 Shield로
  shield verify <파일> <파일>.sig --key <공개키.asc>. 공개키 지문을 개발자가 따로 알려 준 지문과 비교하세요.
  MSI에는 Authenticode 서명이 없어 SmartScreen 경고가 뜰 수 있습니다.

1. 두 개의 창
-------------
- "Shield" (암호화 창): 암호화 / 복호화 / 비밀번호·키 교체 / 디스크 정리 / 알고리즘·정보 / 설정 / 사용법 탭.
- "Shield 파일 관리자": 폴더를 탐색하고 .shd 컨테이너를 열어 내용 보기·일부 추출·파일 추가·항목 삭제를 합니다.
- 각 창의 오른쪽 위 버튼으로 다른 창을 열 수 있습니다. 새 버전이 확인되면 그 옆에 "새 버전" 표시가 나옵니다.
- 아래쪽 진행 표시줄: 단계, 진행률, 속도, 남은 시간, [취소]. 작업 중에는 창을 닫을 수 없습니다
  (덮어쓰기·TRIM·교체 단계는 취소할 수 없습니다).

2. 암호화 (암호화 창)
---------------------
1) [파일 추가…]/[폴더 선택…], 끌어다 놓기, 또는 탐색기에서 여러 항목을 골라 우클릭 "Shield로 암호화".
   여러 항목이면 목록이 보이고 항목마다 [×]로 빼거나 [파일 추가…]로 더할 수 있습니다.
2) 여러 항목일 때 "하나로 묶기"(폴더 이름을 딴 컨테이너 하나) 또는 "각각 따로"(항목마다 .shd)를 고릅니다.
   탐색기에서 여러 개를 골라 열었다면 창이 처음에 이것을 묻습니다.
3) 비밀번호를 두 번 입력합니다. 강도 표시는 흔한 패턴을 반영한 '대략적 추정'입니다.
4) PIM은 권장 기본값(12)을 그대로 두면 됩니다. 필요하면 키 파일을 추가하거나 새로 생성합니다.
5) 압축 강도: 자동(권장) / 빠름(Zstandard) / 균형 / 최대.
6) [암호화 시작] -> 목록 확정 -> 압축 -> 암호화 -> 복원 검증.
- 결과는 "이름.shd"(같은 이름이 있으면 "이름 (2).shd"). 덮어쓰지 않습니다.
- 복원 검증: 만든 파일을 다시 열어 모든 청크를 인증하고, 전부 풀어 원본과 크기·SHA3-512를 비교합니다.
- 비밀번호가 약하면 이유를 보여 주는 확인 창이 뜹니다(기본 버튼 [취소]). 최대 256바이트, 넘으면 거부.
- 붙여넣은 비밀번호는 클립보드에 남습니다. [클립보드 비우기]를 누르세요.

3. 키 파일
----------
- "새 키 파일 생성…": 1~1024 KiB, 처음부터 사용자 전용 권한. 콘솔: shield keyfile <경로> [--size KiB].
- SHA3-512 지문으로 쓰입니다. 빈 파일·한 가지 바이트로만 된 파일·중복은 거부합니다.
- 암호화 대상 안에 있는 키 파일은 쓸 수 없습니다. 키 파일만 쓰려면 위험 확인이 필요합니다.
- 키 파일은 수정하지 말고 다른 곳에 백업하세요. 1바이트만 바뀌어도 쓸 수 없습니다.

4. PIM
------
- Argon2id(메모리 256 MiB, 병렬도 4)의 반복 횟수 = 3 + PIM. 기본 PIM 12 -> 반복 15. 0~64.
- 파일에 저장되지 않으므로 바꿨다면 반드시 기록하세요.

5. 복호화
---------
- .shd를 고르고 같은 비밀번호·PIM·키 파일 -> [복호화 시작]. 본문 전체를 먼저 인증한 뒤에만 풉니다.
- 사용자 전용 임시 폴더에 풀고 검사한 뒤 .shd 옆으로 옮깁니다. 같은 이름이 있으면 "(decrypted)"를 붙입니다.
- 여러 항목을 묶은 컨테이너는 컨테이너 이름의 폴더 안에 풀립니다.
- 인터넷에서 받은 .shd는 풀린 파일마다 같은 다운로드 표시를 붙입니다(Windows Zone.Identifier,
  Linux user.xdg.origin.url 확장 속성).
- 틀린 비밀번호·PIM·키 파일, 손상, Shield 파일이 아님은 모두 같은 메시지입니다.

6. 파일 관리자와 "SHIELD에서 열기"
---------------------------------
- .shd를 두 번 클릭하거나 끌어다 놓거나 우클릭 "SHIELD에서 열기" -> 자격 증명 -> [열기].
- 목록을 읽은 직후 키와 비밀번호는 메모리에서 지웁니다. 열린 뒤에도 검사·추출·추가·삭제 때마다 다시 묻습니다.
- [파일 추가…]/[선택 항목 삭제…]: 매번 확인 창이 뜨고, 스냅숏·저장 장치 경고와 덮어쓰기 횟수(3/7)를 보여 줍니다.
  컨테이너를 새 키로 다시 만들어 검증한 뒤 바꾸고, 이전 컨테이너 데이터는 고른 횟수만큼 덮어써 지웁니다
  (키 영역은 항상 7회). 끝나면 TRIM을 실행합니다.
- 5분 동안 조작이 없거나 [닫기]·창 닫기 시 열린 컨테이너의 목록을 메모리에서 지웁니다.

7. 비밀번호·키 교체
-------------------
- 비밀번호만 변경(빠름): 데이터 키를 새 자격 증명으로 다시 감싸고 이전 슬롯을 7회 덮어씁니다.
- 전체 키 교체: 새 데이터 키·솔트·nonce·패딩으로 다시 암호화·검증·교체한 뒤 이전 컨테이너를 고른 횟수(3/7)만큼
  덮어써 지웁니다. 확인 창에서 횟수를 고르며 스냅숏 경고가 함께 나옵니다.
- 어느 쪽이든 이전 백업본·클라우드 버전 기록·스냅숏은 이전 비밀번호로 계속 열립니다.

8. 덮어쓰기 삭제 (원본 파쇄, 키 교체, 추가·삭제)
----------------------------------------------
- 덮어쓰기 횟수: 3회(00, FF, 난수) 또는 7회(00, FF, 난수, 55, AA, 난수, 난수). 할 때마다 확인 창에서 고르고,
  기본값은 설정 > 암호화. 헤더·키 슬롯 같은 키 영역은 고른 값과 상관없이 항상 7회입니다.
- 덮어쓰기 전에 스냅숏을 확인해 알려 줍니다: Windows 볼륨 섀도 복사본(VSS), Linux btrfs·ZFS 스냅숏, LVM 스냅숏,
  Timeshift, Snapper. Shield는 스냅숏을 지우지 않습니다(관리자 권한이 필요하고 사용자가 판단할 일).
- 끝나면 그 볼륨에 TRIM을 실행합니다(Windows ReTrim, 관리자 아니면 UAC 확인: Windows의 defrag.exe /L이 실행됨 / Linux FITRIM, root가 아니면 pkexec
  안내, LUKS에서 discard가 꺼져 있으면 알림). TRIM이 실패해도 작업은 성공이며 이유를 결과에 적습니다.
- 목록 확정 시점의 파일만, 크기·시각·파일 ID가 그대로일 때만 덮어쓰고 지웁니다. 하드 링크·링크는 건드리지 않습니다.
- 숨은 스트림(ADS)이 있으면 멈추고 포함할지 묻습니다.
- 정직한 한계: SSD·플래시는 쓰기 위치를 바꾸고(웨어 레벨링), btrfs·ZFS 같은 COW 파일 시스템과 스냅숏·클라우드
  폴더는 이전 블록을 남깁니다. 이런 곳에서는 덮어쓰기와 TRIM이 물리적 삭제를 보장하지 않습니다. 처음부터
  전체 디스크 암호화(BitLocker, LUKS)를 쓰는 것이 가장 확실합니다.

9. 디스크 정리 탭
-----------------
- 볼륨 고르기(드라이브 목록 또는 [폴더로 볼륨 선택…]), 저장 장치 종류 표시.
- TRIM 실행, 여유 공간 덮어쓰기(Windows cipher /w, Linux 채우기 파일. 오래 걸리고 SSD 수명 소모, 취소 가능).

10. 비정상 종료 후
------------------
- 평문이 든 임시 폴더가 남으면 다음 실행 때 알림이 뜨고 [지금 덮어쓰고 삭제]로 정리할 수 있습니다.
- 다른 Shield 창이 쓰는 폴더는 알리지 않습니다(Windows·Linux 모두 프로세스 시작 시각으로 확인).

11. 중요한 안전 안내
--------------------
- 비밀번호, PIM, 키 파일 중 하나라도 잃어버리면 누구도 복호화할 수 없습니다.
- 원본 파쇄 전 반드시 복사본으로 복호화를 시험하세요.
- 메모리 잠금, zeroize, 프로세스 보호는 최선의 노력입니다. 같은 사용자 권한의 악성 프로그램, 관리자/root, 커널,
  물리적 접근은 막지 못합니다.
- 히든 볼륨이나 부인 가능 저장 기능은 없습니다.

12. 설정 탭
-----------
분류: 일반 / 보안 / 암호화 / 파일 관리자 / 업데이트. 바꾼 값은 바로 적용되고 원자적으로 저장됩니다.
- 설정 비밀번호(보안 맨 위): 보안 설정을 바꾸려면 먼저 만들고(8자 이상), 이후에는 잠금 해제해야 바뀝니다.
  잠긴 동안 보안 항목은 회색입니다. 자동 잠금이 일어나면 다시 잠깁니다. 틀리면 1초부터 두 배씩 최대 30초 기다립니다.
  비밀번호 자체는 저장하지 않고 Argon2id 검증값만 저장합니다.
  만들기 / 바꾸기 버튼은 늘 눌리며, 쓸 수 없는 비밀번호(8자 미만, 확인 불일치, 너무 김)는 이유를 보여 주고 거부합니다.
  쓸 수는 있지만 약한 비밀번호(12자 미만, 흔한 단어·연속 문자 등)는 암호화처럼 "약한 비밀번호" 확인 창이 뜹니다.
- 보호 항목: 화면 캡처 방지, 마우스 엔트로피, 엔트로피 소스, 명령줄 인자 비밀번호 허용, 기본 덮어쓰기 횟수,
  업데이트 방식, 자동 잠금 시간·최소화 시 잠금·포커스를 잃을 때 잠금, 비밀번호 [보기] 허용, 클립보드 비우기,
  엄격 모드. 설정 비밀번호를 없애면 보호 항목은 기본값으로 돌아갑니다(비밀번호 없이는 기본값만 유지).
- 설정 파일(settings.toml)을 Shield 밖에서 고치면 MAC이 맞지 않아 보호 항목이 안전한 기본값으로 돌아가고
  설정 비밀번호가 해제되며 경고가 뜹니다. auth 줄과 settings.key를 함께 지워도 같습니다(기본값 + 경고).
  2.x 설정 파일은 설정 비밀번호가 없던 판이므로 보호 항목만 경고 없이 기본값으로 바뀝니다.
- 설정 비밀번호를 잊었을 때(복구): 설정 > 일반의 "설정 파일 삭제"(또는 settings.toml과 settings.key를 직접 삭제)
  -> 모든 설정이 기본값(안전한 쪽)으로 돌아가고 새 설정 비밀번호를 만들 수 있습니다. 컨테이너에는 영향이 없습니다.
  위치: Windows %LOCALAPPDATA%\Shield, Linux $XDG_CONFIG_HOME/shield(보통 ~/.config/shield), 포터블은 Shield_data.
- 언어(한국어/English/시스템), 화면 모드(밝게/어둡게/시스템), 날짜 형식, 시작 화면, 기본 PIM, 압축 기본값.
- 파일 관리자: 숨김 파일, 시작 폴더, 정렬, 삭제 전 확인, 우클릭 메뉴(이 사용자) 등록·삭제(포터블·AppImage용).
- 화면 캡처 방지는 Windows에서만 동작합니다. Linux(X11·Wayland)에서는 "사용할 수 없어 해제됨(사유)"으로 표시되고,
  설정 파일에는 고른 값이 남습니다(다음 실행 때 다시 시도).
- 설정 > 일반 > 창 위치 기억(기본 켜짐): 창을 닫은 곳에서 다시 엽니다. 그 위치가 연결된 화면 밖이면 가운데에서
  엽니다. Wayland는 창 위치를 알려 주지 않아 사용할 수 없습니다.
- 탭의 선택(저장 위치 고르기, 묶기, 빈 공간 덮어쓰기, 덮어쓰기 횟수 등)은 다음 실행 때 그대로입니다. 비밀번호,
  키 파일, PIM, 고른 파일과 "원본이 지워짐을 이해함" 같은 확인은 기억하지 않습니다.
- 비밀번호 입력란 아래에 이유가 바로 표시됩니다. 빈 값·확인 불일치·너무 긴 값은 진행할 수 없고, 12자 이하이거나
  흔한·단순한 비밀번호는 경고 후 확인 창에서 고를 수 있습니다.

13. 엔트로피 (설정 > 보안 > 엔트로피 소스)
-----------------------------------------
- 운영체제 난수 생성기(CSPRNG)가 모든 난수의 기본이며 끌 수 없습니다. 실패하면 작업을 멈춥니다.
- 나머지 소스(고해상도 타이머, CPU 지터, 메모리·프로세스·시스템·디스크·네트워크 통계, CPU 하드웨어 난수,
  Windows 성능 데이터, Linux /proc·센서, 창 상태, Shield 창 안의 키 입력 시간과 마우스)는 섞기만 합니다.
  값은 화면·파일·네트워크 어디에도 내보내지 않고, 상태는 "정상 / 약함 / 대기 / 꺼짐"만 표시합니다.
- 콘솔 명령은 창 상태·입력 시간·마우스를 쓰지 않습니다. 키보드 장치(/dev/input)나 화면 전체 마우스 좌표는
  어느 경우에도 읽지 않습니다.
- 소스를 끄려면 설정 비밀번호가 필요합니다(콘솔: shield entropy --disable <소스>).

14. 업데이트와 개발 정보 (설정 > 업데이트)
-----------------------------------------
- 업데이트: 끔(기본) / 확인만 / 자동 다운로드. 자동이어도 설치 전에 반드시 묻습니다. [지금 확인]은 언제든 됩니다.
- GitHub 릴리스(빌드할 때 정한 저장소)를 HTTPS로 확인합니다. 보내는 것은 요청 자체와 User-Agent "Shield-Updater"
  뿐이며, 오프라인이면 아무 말 없이 넘어갑니다(직접 확인한 경우에만 오류 표시).
- 받은 파일은 사용자 전용 임시 폴더에 두고, 내장 공개키로 매니페스트 서명 -> 버전 -> SHA-256 -> 설치 파일 서명을
  모두 확인합니다. 하나라도 실패하면 받은 파일을 지우고 멈춥니다. 같은 버전·낮은 버전은 설치하지 않습니다.
- 설치 전에 입력 중인 비밀번호와 열린 컨테이너를 지웁니다. Windows는 Shield가 닫히고 MSI 설치 프로그램이 뜹니다.
  Linux deb는 pkexec로 관리자 비밀번호를 묻고, AppImage는 같은 위치의 파일을 새 것으로 바꿉니다.
  포터블 exe와 콘솔 전용 파일은 자동으로 바꾸지 않고 릴리스 페이지만 알려 줍니다.
- 개발 정보: [개발 정보 (GitHub)]는 https://github.com/ 주소만 엽니다. [프로그램 무결성 검사]는 실행 파일 옆의
  .sig를 내장 공개키로 검사합니다. 릴리스 키 지문이 함께 표시되니 개발자가 공개한 지문과 비교하세요.

15. 명령줄 (shield)
-------------------
  shield help                                  전체 도움말 (종료 코드 포함). -h, --help, -help도 같음
  shield help encrypt / shield encrypt --help  명령 하나의 옵션 (아무것도 실행하지 않음)
  shield encrypt 보고서.pdf 사진\ -o 묶음.shd   여러 항목 -> 하나 (--separate: 항목마다)
  shield encrypt 비밀.txt --shred --passes 3    끝나면 원본 3회 덮어쓰기 (먼저 묻고 스냅숏 경고)
  shield decrypt 묶음.shd -o 풀_폴더
  shield list 묶음.shd [--json]
  shield add 묶음.shd 새파일.txt --into 문서     shield remove 묶음.shd 문서/새파일.txt
  shield change-password 묶음.shd                shield rekey 묶음.shd --passes 7
  shield keyfile 내.key --size 4                 shield verify 파일 파일.sig [--key 키.asc]
  shield update [--check]                        shield entropy                shield version
  shield gui [encrypt|decrypt|explorer|settings|open <c>]
- 비밀번호는 화면에 아무것도 표시하지 않고 받습니다(길이도 표시하지 않음). Ctrl+U 지우기, Esc·Ctrl+C 취소.
- --reveal: 별도 화면에 입력을 보여 주고, Enter를 누르면 그 화면과 스크롤 기록을 지웁니다.
- --password <값> --allow-arg-secrets: 설정에서 허용한 경우에만, 매번 경고. 명령줄은 다른 프로그램(작업 관리자,
  ps, 셸 기록)에 보이므로 권장하지 않습니다. 환경 변수·파일·파이프로는 비밀번호를 받지 않습니다.
- 키 파일 -k (여러 번), --pim, 새 값은 --new-keyfile, --new-pim, --new-password.
- --yes는 질문에 예로 답하지만 경고는 그대로 출력합니다. --quiet는 오류만, --json은 결과를 JSON 한 줄로
  (비밀 정보는 절대 포함하지 않음).
- 종료 코드: 0 완료, 1 실패, 2 사용법, 3 자격 증명 틀림·손상, 4 서명 불일치, 5 취소, 6 사용 중, 130 강제 중단.
- 첫 Ctrl+C(또는 SIGTERM·SIGHUP)는 작업을 취소하고 임시 파일을 정리합니다. 두 번째는 즉시 끝냅니다.

16. Linux 참고
--------------
- 파일 관리자: Nemo·Dolphin은 설치하면 바로 메뉴가 생깁니다. Nautilus(스크립트)와 Thunar(사용자 동작)는 사용자별
  설정이라 /usr/share/shield/integrate.sh를 본인 계정으로 한 번 실행하세요. 포터블·AppImage는 설정 > 파일 관리자 >
  우클릭 메뉴에서 등록합니다.
- 디스크 전체 암호화가 LUKS라면 discard 옵션이 꺼져 있을 때 TRIM이 하드웨어까지 전달되지 않습니다(알림 표시).
- 프로세스 보호: 코어 덤프 끔(RLIMIT_CORE=0), PR_SET_DUMPABLE=0(같은 사용자의 ptrace·/proc/<pid>/mem 차단),
  mlock. 스왑을 암호화하거나 끄는 것을 권장합니다. 설정·스테이징은 0600/0700 권한입니다.
