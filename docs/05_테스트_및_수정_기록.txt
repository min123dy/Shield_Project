SHIELD 2.0 - 테스트 및 수정 기록
================================

작성일: 2026-11-01
대상: Shield 1.1 → 2.0 개편 작업 (요구 명세: Shield_최종_수정_프롬프트.txt + 사용자 요청)

1. 현재 상태 요약
-----------------
완료:
- 코드 작성, cargo build --release 성공
- cargo test --release: 48개 테스트 모두 통과
- cargo clippy --all-targets -- -D warnings: 경고 0개
- build.ps1 전체 빌드: -NoSign, -Sign 두 경로 모두 성공 (Shield.msi, dist\ 생성)

- 실행 파일 기동: 두 창 모두 4가지 인수로 정상 실행·정상 종료 (3-3)
- 프로세스 보호: 같은 사용자 프로그램의 메모리 읽기·쓰기·스레드 생성·강제 종료 차단 확인 (3-4)
- cargo audit: 취약점 1건(Windows에서는 해당 없는 Unix 경로), 경고 4건 (3-5)

아직 하지 않은 것 (8절에 자세히):
- GUI 안의 버튼·입력을 직접 눌러 보는 수동 확인
- 실제 설치·업그레이드·제거와 우클릭 메뉴 확인
- 관리자 권한 프로그램·실제 DLL 주입 도구에 대한 시험
- Gpg4win(정식 GnuPG)으로 서명 (Git에 들어 있는 gpg로만 시험)

사용자 요청 해석:
- "Argon2id 메모리 256메가비트" → 256 MiB로 적용했습니다.
  256메가비트는 32 MiB로, 기존 128 MiB보다 약해지기 때문입니다.
  32 MiB를 원했다면 format.rs의 KDF_MEM_KIB 한 줄만 바꾸면 되지만 새 형식 버전이 됩니다.

2. 테스트 환경
--------------
- Windows 10 Pro 10.0.19045 x64, 메모리 31.7 GB
- Rust 1.99.1 (rustup), clippy
- .NET SDK + WiX 5.0.2 (프로젝트 로컬 도구)
- gpg: Git for Windows에 포함된 GnuPG 2.4.9 (MSYS 빌드)

3-4. 프로세스 보호 확인 (명세 19번)
  같은 사용자, 관리자 권한 아닌 PowerShell에서 실행 중인 Shield를 OpenProcess로 열어 봄:
    PROCESS_VM_READ (메모리 읽기)              거부 (오류 5, 접근 거부)
    PROCESS_VM_WRITE|VM_OPERATION (메모리 쓰기) 거부
    PROCESS_CREATE_THREAD (스레드 주입)         거부
    PROCESS_TERMINATE (강제 종료)               거부
    WRITE_DAC (보호 해제 시도)                  거부
    PROCESS_DUP_HANDLE                         거부
    PROCESS_QUERY_LIMITED_INFORMATION          허용 (의도: 탐색기·작업 표시줄 동작용)
    SYNCHRONIZE                                허용 (의도)
  한계 (확인됨/설계상):
    - Shield를 실행한 프로그램(탐색기, 명령 창 등)은 보호가 걸리기 전에 전체 권한 핸들을 받습니다.
      그 핸들은 막을 수 없습니다.
    - 관리자 권한이나 SeDebugPrivilege를 가진 프로그램은 막지 못합니다 (관리자 상태로는 시험하지 않음).
    - 실제 DLL 주입 도구로는 시험하지 않았습니다.

3-5. 의존성 취약점 검사 (cargo audit 0.22.2, 권고 DB 1395건, 의존성 365개)

    webbrowser 0.8.15 - RUSTSEC-2026-0257 "Unix BROWSER 처리에서 브라우저 인수 주입" (해결: 1.2.2 이상)
    경로: eframe 0.27 → egui-winit 0.27 → webbrowser (eframe이 무조건 켜는 기능이라 끌 수 없음)

          Shield 화면에는 브라우저를 여는 링크가 없습니다. 실제 위험은 낮다고 보지만, 근본 해결은
          eframe을 0.3x로 올리는 큰 업그레이드(화면 코드 API 변경)가 필요해 이번에는 하지 않았습니다.

    (zbus 계열은 Linux 전용 의존성이라 Windows 빌드에 들어가지 않음, ttf-parser는 글꼴 읽기용)

4. 테스트·검토 중 발견한 문제와 수정
-----------------------------------
(문제 → 원인 → 수정 순)

4-1. 프로그램 코드
 1) 파일 추가 시 기존 항목의 평문이 디스크에 풀림
    → 처음 구현은 기존 컨테이너를 임시 폴더에 풀어 다시 압축했음 (명세의 "평문 디스크 저장 금지"에 어긋남)
    → archive::copy_entries를 추가해 기존 7z(SecTemp A)에서 새 7z(SecTemp B)로 항목을 직접 옮기면서
      SHA3-512를 계산하도록 변경. 이제 평문이 디스크에 따로 생기지 않습니다.
 2) 두 창을 함께 열면 한 창의 작업 중 임시 폴더를 다른 창이 "남은 폴더"로 알리고 지울 수 있음
    → 기록 파일에 경로만 있었음
    → 기록에 소유 프로세스 번호(PID)를 넣고, 아직 실행 중인 프로세스의 폴더는 알리지 않도록 수정.
      테스트도 "죽은 프로세스가 남긴 폴더만 감지"하도록 바꿈.
 3) 작업 스레드가 비정상 종료되면 결과를 영원히 기다림 (1.1부터 있던 문제)
    → 채널이 끊긴 경우를 처리하지 않았음
    → job.rs에서 catch_unwind로 패닉을 잡고, 끊긴 채널도 실패로 보고.
 4) Argon2 작업 메모리를 해제한 뒤에 잠금 해제함
    → 순서 오류
    → 잠긴 상태에서 0으로 지움 → 잠금 해제 → 해제 순서로 수정.
 5) 폴더 바로가기(링크)를 대상으로 고르면 목록 만들기 실패
    → 링크를 따라간 실제 경로에서 상대 경로를 계산하려 했음
    → 항목 이름을 직접 이어 붙이는 방식으로 바꾸고, 맨 위 링크만 실제 경로로 해석.
      원본 파쇄와 함께 링크를 고르면 거부.
 6) 복호화 저장 위치 계산 오류 (코드 검토에서 발견)
    → 부모 폴더 경로를 한 번 더 이어 붙임
    → parent_dir(src)를 그대로 쓰도록 수정.
 7) 테스트에서 Header에 Debug가 없어 컴파일 실패
    → Header에는 파일 키(DEK)가 들어 있어 Debug를 붙이면 로그로 키가 샐 수 있음
    → Debug를 붙이지 않고 테스트 쪽을 .err().unwrap()으로 바꿈.
 8) 기록 파일 구분 문자(탭)가 소스에 실제 탭 문자로 들어가 컴파일 실패
    → 상수 TAB(0x09)로 대체.
 9) clippy 경고 9종 (사용하지 않는 함수 2개, 복잡한 타입, 인수 8개, 문서 주석 형식, div_ceil 등)
    → 모두 수정하거나 이유가 있는 곳만 명시적으로 허용. 최종 경고 0개.
10) mgr_app.rs가 543줄로 500줄 제한 초과
    → 창 그리기(eframe::App)를 mgr_views.rs로, 테스트를 mgr_tests.rs로 분리.

4-2. 빌드 스크립트 (build.ps1)
 1) PowerShell 5.1에서 gpg가 정상 진행 메시지를 stderr로 내면 스크립트가 오류로 중단
    → $ErrorActionPreference = Stop 상태에서 네이티브 stderr가 오류로 처리됨
    → gpg 호출 함수 안에서만 Continue로 바꾸고 종료 코드로 성공을 판단.
 2) 경로 변환 함수 이름 GP가 PowerShell 기본 별칭 gp(Get-ItemProperty)와 충돌해 호출되지 않음
    → 별칭이 함수보다 우선함
    → ConvertTo-GpgPath로 이름 변경.
 3) Git for Windows의 gpg가 C:\... 경로를 이해하지 못해 "No agent running" 오류
    → MSYS 빌드는 /c/... 형식 경로만 이해함
    → Git gpg를 쓸 때는 경로를 /c/... 로 바꿔 넘기고, Gpg4win이 있으면 그것을 우선 사용.
 4) 소스 zip에 WiX 확장 캐시(.wix, DLL 1.7 MB)와 작업 도구 기록(.claude-flow)이 들어감
    → 제외 목록에 없었음
    → .wix, .claude, .claude-flow, .swarm, .hive-mind, node_modules 제외. zip 59개 → 43개 파일, 1.8 MB → 177 KB.
 5) SHA256SUMS.txt를 sha256sum -c로 읽을 수 없음
    → CRLF 줄바꿈과 BOM
    → LF 줄바꿈, BOM 없이 저장.
 6) 편집 중 build.ps1 앞에 BOM이 두 번 들어가 구문 오류
    → BOM 한 번으로 복구하고 PowerShell 5.1 구문 분석기로 확인.

7. 남은 위험
------------
- egui가 입력 문자열과 화면의 파일 이름을 내부에 복사해 두며 지울 수 없습니다.
- argon2 라이브러리는 레인 4개를 차례로 계산합니다(보안 강도 같음, 속도 이점 없음).
- Zstandard는 레벨만 지정 가능하고 압축은 단일 스레드입니다.
- 프로세스 보호는 같은 사용자 권한의 악성 프로그램·관리자·커널을 막지 못합니다.
- SSD·스냅샷·클라우드 폴더에서는 파쇄가 물리적 삭제를 보장하지 않습니다.
- 외부 보안 감사를 받지 않았습니다.
