SHIELD 2.1.0 - 프로젝트 설명
============================

1. 범위
-------
이 문서는 소스 구조, 암호 구성, 파일 형식과 알려진 한계를 설명합니다.
테스트로 확인한 것과 확인하지 않은 것은 8절에 따로 적었습니다.
2.0에서 2.1.0으로 바뀐 내용은 06_2.1.0_수정_기록.txt에 있습니다.

2. 실행 파일과 창
-----------------
shield.exe 하나에 창이 두 개 있습니다. 기본 창 크기는 1040x700, 최소 크기는 800x560입니다.
- 암호화 창 (기본): 탭 = 암호화 / 복호화 / 비밀번호·키 교체 / 디스크 정리 / 알고리즘·정보 / 설정 / 사용법
- 파일 관리자 창 (--manager, --open): 주소 칸·목록으로 폴더를 탐색하고 .shd 컨테이너를 엽니다.
  컨테이너를 열면 탭 = 파일 / 정보 / 사용법. 선택 추출, 전체 추출, 파일·폴더 추가, 선택 항목 삭제, 본문 전체 검사.
두 창은 서로를 같은 실행 파일로 띄웁니다(std::env::current_exe). 상태는 공유하지 않습니다.
설정(언어, 밝기 모드, 화면 캡처 방지 등)은 시작할 때 한 번 읽고, 바꾸면 바로 적용하며 원자적으로 저장합니다.
UPX로 압축한 포터블 exe(Shield_v{버전}_portable.exe)는 설치 없이 실행하며 설정을 exe 옆 Shield_data 폴더에 저장합니다.

------------

enc_app.rs     암호화 창 상태·입력 검증·작업 시작/완료, 유휴 120초 비밀번호 삭제

4. 암호 구성
------------
- 데이터·메타·키 슬롯·임시 파일: XChaCha20-Poly1305 (256비트 키, 192비트 nonce)
- KDF: Argon2id v1.3, 메모리 256 MiB(262144 KiB), 병렬도 4, 반복 3+PIM (PIM 0~64, 기본 12)
  사용자 요청 "256메가비트"는 256 MiB로 해석했습니다. 256메가비트(=32 MiB)는 기존 128 MiB보다 약해지기 때문입니다.
  메모리·병렬도는 형식 버전에 묶인 상수이며 슬롯 AAD에 들어 있습니다(값을 바꾸면 새 형식 버전).
  argon2 0.5 크레이트는 4개 레인을 한 스레드에서 차례로 계산합니다(보안 강도 동일, 속도 이점 없음).
- 파일 키(DEK) 32바이트를 KEK로 감싸 슬롯 2개 중 무작위 하나에 저장, 다른 슬롯은 난수.
- 실패 메시지: 슬롯·메타 인증 전의 모든 실패는 "비밀번호가 틀렸거나 손상된 파일" 하나로 통일.
  알 수 없는 버전·ID는 인증에 성공한 뒤에만 "지원하지 않는 형식"으로 거부.
- 비밀번호: 입력 경계에서 Unicode NFC로 정규화한 UTF-8 바이트를 모든 작업에 동일하게 사용, 최대 256바이트.
  256바이트를 넘으면 잘라 쓰지 않고 거부합니다.
- 난수: 키·솔트·nonce는 OS 난수가 기본이며 마우스 엔트로피는 보조로만 섞입니다. 마우스 입력이 없거나
  설정에서 꺼도 보안 수준이 낮아지지 않습니다.

SHA3 사용 결정표
  키 파일 지문                 SHA3-512 (라벨 "SHIELD-KF-v2", 여러 파일은 정렬·중복 거부 후 결합)
  복원 검증(파쇄 전 비교)      SHA3-512 (파일별)
  엔트로피 풀                  SHA3-512
  키 등급 난수(DEK, 솔트 등)   SHAKE256 (라벨 + OS 난수 64B + 풀 + 카운터)
  배포 해시 목록               SHA-256 (build.ps1, 기존 출력 형식 유지 - 프로그램 내부 암호와 무관)
  바꾸지 않은 것               Poly1305 태그(AEAD의 일부), Argon2 내부 BLAKE2b(알고리즘 정의의 일부)

5. 파일 형식 v2
---------------
  [슬롯 0: 88B][슬롯 1: 88B]  슬롯 = 솔트16 + nonce24 + 감싼 DEK32 + 태그16
  [nonce 접두사 15B]
  [메타 512B + 태그16]         AAD = "SHIELD-v2-META" + 접두사
  [청크 64 KiB + 태그16] ...   nonce = 접두사 + 종류(0 데이터/1 마지막/2 메타) + 카운터8 BE,
                               AAD = "SHIELD-v2-DATA" + 메타 태그
헤더 719바이트. 메타: 형식 버전, AEAD/해시/KDF ID, KDF 메모리·레인, 압축 방식·레벨·사전, 청크 크기,
실제 길이, 패딩 길이, 플래그, 파일·폴더 수, 총 해제 크기, 생성 시각, 원래 이름. 남은 바이트는 0이어야 함.
파일 크기는 패딩 길이로부터 정확히 계산되며, 다르면 거부합니다(잘림·덧붙임 탐지).
패딩은 0 ~ clamp(실제 길이/16, 64 KiB, 1 GiB) 무작위, 내용은 0이며 인증 후 0인지 확인합니다.
고정 매직 바이트는 없지만, 그것이 암호문을 난수와 구별 불가능하게 만든다는 보장은 아닙니다.

6. 안전 장치
------------
- 암호화: 대상 목록 확정(파일 ID·크기·수정 시각, 크기 한도는 이 단계부터 적용) → 압축(SecTemp) →
  암호화(.part) → 다시 열어 전체 인증 → 7z 구조·제한 검사 → 7z 목록(파일 수·폴더 수·전체 크기)을
  인증된 메타데이터와 대조 → 전체 해제하며 SHA3-512 비교 → 덮어쓰지 않는 이름 변경 → (선택) 파쇄.
- 파쇄: 목록에 있고 바뀌지 않은 파일만. 핸들 기준으로 파일 ID·링크 수 확인, 하드 링크(nlink>1) 거부,
  링크는 따라가지 않음, 덮어쓰기 → 크기 0 → 무작위 이름 → 같은 파일인지 재확인 → 핸들로 삭제.
  숨은 스트림(ADS)이 있으면 멈추고, 포함해서 파쇄할지 묻습니다(비밀번호 다시 입력).
  파쇄·여유 공간 덮어쓰기·TRIM이 실패하면 성공이 아니라 오류로 알리며 결과 .shd는 남습니다.
- 복호화: 본문 전체 인증(SecTemp) → 7z 검사와 메타데이터 대조 → 사용자 전용 스테이징 폴더에 해제
  (인증된 전체 크기를 넘으면 그 자리에서 중단) → 덮어쓰지 않고 이동.
  .shd가 인터넷에서 받은 파일이면 그 다운로드 표시(Zone.Identifier)를 풀린 파일마다 붙입니다
  (7-Zip의 CVE-2025-0411과 같은 유형의 문제를 막기 위한 것). 엄격 모드에서는 붙이지 못하면 결과를 지웁니다.
- 해제 제한: 항목 100만 개, 깊이 64, 경로 1024자, 구성 요소 255바이트, 항목 4 TiB, 합계 16 TiB,
  압축률 10000배(64 MiB부터 항상 적용), LZMA2 사전 64 MiB, Zstandard 창 128 MiB(디코더 기본), 장치 이름·ADS·
  끝 공백/마침표·절대 경로·.. ·백슬래시 포함 이름·대소문자만 다른 중복·링크 항목 거부.
- SecTemp: 작업마다 새 키, 블록 AAD에 색인·쓰기 카운터 포함(재사용·교체·구멍·잘림 탐지), 삭제 실패는 보고,
  시작 전 여유 공간 확인, 블록 수 상한과 try_reserve(메모리 확보 실패는 오류로 보고).
- 임시 평문 폴더: 만들기 전에 기록(journal)에 먼저 등록하고, 등록에 실패하면 만들지 않습니다.
  기록이 손상되면 빈 목록으로 보지 않고 오류로 알린 뒤 "복구 검사"를 제안합니다. 삭제(덮어쓰기)가 실패하면
  기록 항목을 남겨 다음 실행에서 다시 알립니다. 소유 확인은 프로세스 번호 + 시작 시각이고, 지울 때 이름·
  실제 폴더 여부·정규 경로를 확인합니다.
- 동시 작업: 컨테이너마다 프로세스 간 잠금(별도 잠금 파일, LockFileEx). 읽기는 함께, 쓰기는 혼자.
  3초 안에 잡지 못하면 "다른 작업이 사용 중" 오류와 [다시 시도] 버튼. 키 유도보다 잠금을 먼저 잡습니다.
- 열린 컨테이너: 목록을 읽은 직후 키·비밀번호를 지우고 목록만 남깁니다. 검사·추출·추가·삭제를 할 때마다
  비밀번호(PIM·키 파일 포함)를 다시 묻습니다.
- 비밀번호 변경: 새 슬롯 기록·fsync → 다시 읽어 같은 DEK인지 확인 → 이전 슬롯 7회 덮어쓰기.
- 전체 키 교체·파일 추가·항목 삭제: 새 DEK·솔트·nonce·패딩으로 재암호화 → 전체 검증 → 원본 크기·수정 시각
  불변 확인 → 원자적 교체(MoveFileEx REPLACE_EXISTING | WRITE_THROUGH).
- 약한 비밀번호(짧음, 흔한 패턴 등)는 이유를 보여 주는 확인 창을 거칩니다. 기본 버튼은 [취소]이고 Esc도 취소입니다.
- 키 파일은 만들 때부터 사용자 전용 권한(보호된 DACL)으로 생성합니다.
- 작업 스레드 패닉은 실패로 보고되고, 임시 자료는 Drop 경로에서 정리됩니다.

7. 알려진 한계
--------------
- 같은 사용자 권한의 악성 프로그램, 관리자 권한, 커널, 물리적 접근은 막지 못합니다.
  프로세스 DACL·DLL 검색 경로 제한·이미지 로드 정책은 일부 공격을 어렵게 할 뿐입니다.
  같은 사용자(비관리자)의 메모리 읽기·쓰기·스레드 생성·강제 종료가 거부되는 것은 확인했지만, Shield를 실행한
  프로그램이 미리 받은 핸들과 관리자 권한 프로그램은 막지 못합니다(05_테스트_및_수정_기록.txt 3-4).
- 화면 캡처 방지는 소프트웨어 캡처(스크린샷, 화면 녹화, 화면 공유)만 막습니다. 휴대폰 카메라, 하드웨어 캡처
  장치, 커널 수준에서 동작하는 악성 프로그램은 막지 못합니다. 실제 창에서의 동작은 직접 확인하지 못했습니다.
- 마우스 엔트로피는 보조 수단입니다. 막대가 100%가 되어도 암호학적 보증이 아니며, 강도는 OS 난수가 보장합니다.
- egui는 키 입력 이벤트 문자열(Event::Text/Paste)과 화면에 그린 텍스트(파일 이름 등)를 내부에 복사하며
  지우지 않고 해제합니다. Shield는 이벤트를 즉시 잠긴 버퍼로 옮기지만 그 사본까지 지울 수는 없습니다.
  비밀번호 [보기]를 켜면 비밀번호가 텍스트로 그려지므로 같은 한계가 적용됩니다.
- 메모리 잠금(VirtualLock)은 실패할 수 있으며, 실패하면 화면에 경고를 표시합니다.
- 암호문 크기로 원본 크기의 대략적 범위를 알 수 있습니다. 디스크 사용량은 최대 약 6% 늘 수 있습니다.
- SSD·USB·스냅샷·클라우드 폴더에서는 덮어쓰기·TRIM이 물리적 삭제를 보장하지 않습니다.
- NTFS가 아닌 드라이브(FAT32, USB 등)는 숨은 스트림·파일 ID가 없어 해당 검사를 시험하지 못했습니다.
- 비밀번호 변경·전체 키 교체 전의 백업본은 이전 비밀번호로 계속 열립니다.
- Zstandard 인코더는 레벨만 지정할 수 있고 단일 스레드입니다.
- 강도 표시는 흔한 패턴만 반영한 대략적 추정입니다.
- 의존성 eframe 0.27에 딸린 webbrowser의 취약점 1건(Unix 전용, Windows 무관)이 있습니다(05 문서 3-5).
- 독립적인 외부 보안 감사를 받지 않았습니다.
