SHIELD 3.0.0 - 프로젝트 설명
============================

1. 범위
-------
이 문서는 소스 구조, 실행 파일, 암호 구성, 파일 형식, 안전 장치와 알려진 한계를 설명합니다.
2.1.0에서 3.0.0으로 바뀐 내용과 OS별 지원 표는 06_3.0.0_수정_기록.txt, 테스트와 보안 점검 결과는
05_테스트_및_점검_기록.txt에 있습니다. 2.x 기록은 docs\history에 그대로 남겼습니다.
English: docs\en\01_overview.txt

2. 실행 파일과 창 (Windows · Linux)
-----------------------------------
- shield-gui (Windows: shield-gui.exe, 콘솔 창 없음): 창 두 개
  · 암호화 창: 암호화 / 복호화 / 비밀번호·키 교체 / 디스크 정리 / 알고리즘·정보 / 설정 / 사용법
  · 파일 관리자 창(--manager, --open): 폴더 탐색, .shd 열기, 선택·전체 추출, 추가, 삭제, 본문 검사
  · 탐색기·파일 관리자 메뉴가 부르는 인수: --encrypt-multi <항목...>, --decrypt <c>, --open <c>, --manager, --settings
- shield (Windows: shield.exe, 콘솔): 명령줄 프로그램. MSI는 설치 폴더를 시스템 PATH에 추가하고,
  deb는 /usr/bin/shield로 설치합니다. gui 기능을 넣은 빌드는 "shield gui ..."로 창도 엽니다.
- 콘솔 전용 빌드(shield-console_v3.0.0_*): GUI 의존성(eframe, rfd 등)이 전혀 없는 단일 파일.
  Linux 판은 musl 정적 링크입니다.
- 포터블: Shield_v3.0.0_x64_portable.exe(이름이 _portable로 끝나면 설정을 exe 옆 Shield_data에 저장),
  Linux AppImage(Shield_v3.0.0_x86_64.AppImage, "cli <명령>"으로 콘솔 명령).
- 여러 항목을 탐색기에서 골라 암호화하면 프로세스가 항목마다 하나씩 뜹니다. 각 프로세스는 사용자 전용
  data_dir\spool에 목록을 쓰고, leader.lck을 잡은 하나만 0.7초 동안 조용해질 때까지(최대 8초) 모아
  창 하나를 엽니다. 창은 "하나로 묶기 / 각각 따로"를 묻고, 목록에서 항목을 빼거나 더할 수 있습니다.

3. 워크스페이스와 크레이트
--------------------------

    windows/  fs(파일 ID, 보호된 DACL, MoveFileEx), mem(VirtualLock, 프로세스 완화 정책), storage(디스크 종류,
              TRIM(ReTrim, 필요하면 UAC로 System32 defrag /L), VSS 확인, cipher /w), shell(HKCU 메뉴), sys(DPAPI, msiexec 등),
              entropy(보조 엔트로피 소스), install(MSI 업데이트)
    linux/    fs(O_NOFOLLOW, 0600/0700, renameat2 RENAME_NOREPLACE, 디렉터리 fsync), mem(mlock, setrlimit
              RLIMIT_CORE=0, PR_SET_DUMPABLE=0), storage(/proc/self/mountinfo, rotational, dm-crypt·LVM·NVMe,
              FITRIM, LUKS discard 확인, btrfs·ZFS·LVM·Timeshift·Snapper 스냅숏 확인, 빈 공간 채우기),
              shell(.desktop, MIME, Nautilus·Nemo·Dolphin·Thunar), sys(XDG 경로, /proc 시작 시각, pkexec),

crates/shield-core      OS 분기 없음(cfg(windows) 없음). 엔진과 모든 문자열 표.

    password, lock(std File::try_lock = Windows LockFileEx / Linux flock), wipe, ads, harden, progress,
    job, i18n + lang\(ko/en × core/ui/v3/cli, 사용법), help, ui_fmt, outname(출력 이름 규칙),
    entropy\(풀 v4, health 검사), settings(+ settings_auth: 설정 비밀번호), sigverify(OpenPGP 검증),
    buildinfo(저장소 URL, 내장 공개키, 자체 무결성 검사), update(GitHub 릴리스 확인·다운로드·검증·설치),
    spool(여러 항목 모으기), cross_os_tests(두 OS에서 만든 컨테이너 상호 열기)
    build.rs: SHIELD_REPO_URL(https://github.com/<owner>/<repo>만 허용, 그 밖은 빌드 중단)과
              SHIELD_PUBKEY_PATH(기본 keys/release_key.asc, 비밀키가 들어 있으면 빌드 중단)를 내장
crates/shield-gui       egui 창. lib(run(Start)) + bin shield-gui.
    enc_app/enc_jobs/enc_views(암호화 창), mgr_app/mgr_ops/mgr_views(파일 관리자), settings_view,
    settings_pw(설정 비밀번호, Argon2id는 작업 스레드), update_ui(업데이트·개발 정보·무결성 검사),

4. 암호 구성 (2.1.0과 같음, 약화한 것 없음)
-------------------------------------------
- 데이터·메타·키 슬롯·임시 파일: XChaCha20-Poly1305 (256비트 키, 192비트 nonce)
- KDF: Argon2id v1.3, 메모리 256 MiB, 병렬도 4, 반복 3+PIM (PIM 0~64, 기본 12)
- 헤더 인증, 암호화된 메타데이터(형식 버전·알고리즘 ID도 안에만 있음), SHA3-512 복원 검증
- 키는 작업이 끝나면 지우고 메모리에 남겨 두지 않으며, 작업마다 비밀번호를 다시 묻습니다(창·콘솔 모두).
- 비밀번호: Unicode NFC, 최대 256바이트(넘으면 거부), 상수 시간 비교

3.0에서 추가된 암호 사용
  설정 비밀번호      Argon2id(128 MiB, t=3, p=4, 솔트 16B) -> HKDF-SHA3-512("SHIELD-SET-v3")로
                     검증값 32B와 MAC 키 32B. 보호 항목은 HMAC-SHA3-512("SHIELD-SET-MAC-v2\n" + 내용)
                     (3.0.0이 쓴 v1 MAC도 읽음). MAC 키 파일은 DPAPI + 추가 엔트로피로 봉인
  난수 풀            SHA3-512 흡수, 출력 HKDF-SHA3-512(OS 난수 64B | 풀 | 카운터), 출력 후 풀 재혼합
  업데이트·무결성    OpenPGP 분리 서명(rPGP 0.21, brainpool은 RustCrypto bp256/bp384 + ecdsa),
                     서명된 릴리스 매니페스트의 SHA-256, HTTPS(ureq 3 + rustls, 인증서 검증)
  배포 해시 목록     SHA-256 (SHA256SUMS.txt, sha256sum -c 형식)

5. 파일 형식 v2 (바뀌지 않음)
-----------------------------
  [슬롯 0: 88B][슬롯 1: 88B][nonce 접두사 15B][메타 512B + 태그 16][청크 64 KiB + 태그 16] ...
헤더 719바이트. 매직 바이트 없음. Windows와 Linux가 바이트 단위로 같은 형식을 쓰며, 두 OS에서 만든
고정 테스트 파일(tests/fixtures/container)을 서로 여는 테스트가 있습니다. 2.x 컨테이너는 그대로 열립니다.
여러 항목을 하나로 묶으면 메타의 이름이 컨테이너 이름인 폴더가 되고, 복호화하면 그 폴더 안에 풀립니다.

6. 3.0의 새 안전 장치 (요약, 자세한 것은 06 문서)
-------------------------------------------------
- 엔트로피: OS CSPRNG가 항상 기본이며 끌 수 없음. OS 난수가 실패하면 작업을 멈춤. 보조 소스는 섞기만
  하며 상태는 "정상/약함"만 표시(값은 표시·저장·전송하지 않음). 콘솔 명령은 창 상태·입력 시간·마우스를
  수집하지 않음. /dev/input과 Wayland 전역 좌표는 쓰지 않음.
- 덮어쓰기: 3회 또는 7회(매번 묻고 기본값은 설정), 키 영역은 항상 7회, 덮어쓰기 전 스냅숏 경고, 끝나면 TRIM
  (실패는 표시만 하고 작업은 성공). 전체 키 교체·파일 추가·삭제 뒤의 이전 컨테이너도 덮어씀(2.1은 하지 않았음).
- 업데이트: 기본 꺼짐, 확인만/자동 다운로드 선택, 설치 전 항상 확인, 엄격한 vX.Y.Z 태그, 같은·낮은 버전 거부,
  서명 실패 시 파일 삭제 후 중단, 식별 정보 전송 없음(User-Agent "Shield-Updater"만), 오프라인이면 조용히 실패,
  설치 전에 비밀 정보 삭제, 사용자 전용 임시 폴더.
- 콘솔: 에코 없는 비밀 입력, 민감 화면(--reveal)은 Enter 후 화면과 스크롤 기록 삭제, 인자 비밀번호는 기본 꺼짐
  (설정 + --allow-arg-secrets + 매번 경고), 환경 변수·파일 입력 미지원, 첫 Ctrl+C·SIGTERM·SIGHUP은 작업 취소,
  두 번째는 엔트로피 풀을 지우고 종료.
- 설정 보호: 보안 설정(캡처 방지, 마우스 엔트로피, 엔트로피 소스, 인자 비밀번호, 기본 덮어쓰기 횟수, 업데이트,
  자동 잠금, 포커스를 잃을 때 잠금 등)은 설정 비밀번호를 넣어야 바뀜. 파일이 밖에서 바뀌면 MAC 불일치로 보호
  항목을 안전한 기본값으로 되돌림. 설정 비밀번호가 없는 파일에는 기본값만 유효함(auth 줄과 settings.key를 지워도
  기본값과 경고만 남음). 틀린 비밀번호는 1초부터 두 배씩 최대 30초 기다림.

7. 알려진 한계
--------------
- 같은 사용자 권한의 악성 프로그램, 관리자/root, 커널, 물리적 접근은 막지 못합니다.
- Linux의 설정 MAC 키 파일(settings.key)은 0600 권한 파일일 뿐 봉인되지 않습니다(Windows는 DPAPI + 추가
  엔트로피: 모든 DPAPI 데이터를 한꺼번에 푸는 도구는 막지만, Shield를 아는 같은 사용자 프로그램은 막지 못함).
  같은 사용자 권한이면 키를 읽어 MAC을 새로 만들 수 있습니다. 설정 보호는 다른 계정과 실수를 막는 장치입니다.
- 설정 비밀번호의 재시도 지연은 프로세스 안에서만 셉니다. 콘솔을 다시 실행하면 0부터 시작하며,
  그때는 Argon2id(128 MiB) 비용만 남습니다.
- 자체 무결성 검사는 바뀐·손상된 실행 파일을 찾지만, 내장 공개키까지 바꾼 프로그램은 찾지 못합니다.
  화면에 표시된 지문을 개발자가 따로 공개한 지문과 비교해야 합니다.
- brainpoolP512r1 서명 키는 지원하지 않습니다(256/384, Ed25519, NIST P 곡선, RSA는 rPGP가 지원).
- 인자 모드로 준 비밀번호는 Shield가 자기 복사본을 지워도 운영체제의 명령줄 사본(작업 관리자, /proc/<pid>/cmdline,
  셸 기록)에 남습니다. 그래서 기본으로 꺼져 있습니다.
- Windows 콘솔에서 TRIM은 관리자 권한이 없으면 UAC 창을 띄웁니다. 응답하지 않으면 그 단계에서 기다립니다.
- 같은 사용자 권한의 프로세스는 검사와 사용 사이(TOCTOU)에 파일을 바꿀 수 있습니다. Shield는 핸들·파일 ID·
  크기·시각을 다시 확인해 대부분 거부하지만 모든 경우를 막지는 못합니다.
- SSD·플래시·COW(btrfs·ZFS)·스냅숏·클라우드 폴더에서는 덮어쓰기·TRIM이 물리적 삭제를 보장하지 않습니다.
- Wayland·X11에서는 화면 캡처 방지를 지원하지 않습니다(설정에 "사용할 수 없어 해제됨(사유)"으로 표시).
- Wayland에서는 창 위치를 기억할 수 없습니다(창 관리자가 위치를 정함).
- AppImage와 GUI는 시스템의 GTK3를 씁니다. Linux 스왑이 암호화되지 않았다면 mlock이 실패한 메모리는
  디스크로 나갈 수 있습니다(암호화된 스왑 또는 스왑 없음 권장).
- egui가 입력 이벤트와 그린 텍스트를 내부에 복사하는 한계(2.x와 같음)는 그대로입니다.
- 독립적인 외부 보안 감사를 받지 않았습니다.

------------
