SHIELD 1.1 - 빌드 방법
======================

1. 프로젝트 폴더 구조
---------------------
프로젝트 ZIP을 푼 뒤 아래 구조를 유지하십시오.

  Shield_Project/
    Cargo.toml
    build.rs                (exe 아이콘/버전 리소스)
    build.ps1
    installer.wxs
    installer.ko-KR.wxl     (설치 화면 문구)
    src/                    (main, ui, views, help, engine, keyfile, archive, wipe,
                             entropy, progress, sectemp, harden, icon)
    docs/
      01_프로젝트_설명.txt
      02_빌드_방법.txt
      03_사용_방법.txt      (설치 폴더에 함께 설치되는 사용 설명서)
      04_설치_안내.txt      (설치 첫 화면의 주의사항/사용법)

installer.wxs는 target/release/shield.exe, docs/03_사용_방법.txt, 그리고 build.ps1이
docs/04_설치_안내.txt로부터 만든 target/installer/notice.rtf를 입력으로 사용합니다.
파일명과 폴더 구조를 변경하면 WiX Source 경로도 함께 수정해야 합니다.

2. 필요한 도구
--------------
- Windows 10 또는 Windows 11 x64
- Rust stable toolchain 및 Cargo
- Windows용 Rust 빌드에 필요한 링커 도구와 Windows SDK(Visual Studio C++ Build Tools 등)
  (build.rs가 아이콘 리소스를 넣을 때 Windows SDK의 rc.exe를 사용)
- .NET SDK 6 이상
- WiX Toolset 5.0.2 (프로젝트의 .config\dotnet-tools.json에 고정; 전역 설치 불필요)
- 최초 의존성 다운로드 및 WiX 설치를 위한 인터넷 연결

설치 확인:

  rustc --version
  cargo --version
  dotnet --version

WiX는 build.ps1이 프로젝트의 로컬 .NET 도구로 복원합니다. 전역 WiX 설치/버전은 변경하지 않습니다.
프로젝트는 WiX 5.0.2를 고정해 WiX 7의 OSMF EULA 강제 확인으로 빌드가 막히는 상황을 피합니다.
WiX 5는 현재 보안 지원 기간이 끝난 구버전이므로 빌드 도구로만 사용하며, 결과 MSI에 WiX 실행 파일은 포함되지 않습니다.

3. 빌드
-------
PowerShell에서 프로젝트 루트로 이동한 뒤 실행합니다.

  Set-ExecutionPolicy -Scope Process Bypass
  .\build.ps1

스크립트는 다음 5단계를 수행하며, 어느 단계든 실패하면 즉시 중단합니다.
  [1/5] cargo build --release (버전은 Cargo.toml의 version)
  [2/5] cargo test --release
  [3/5] WiX 5.0.2 로컬 도구 복원 + WixToolset.UI / WixToolset.Util 확장 설치(.wix 폴더)
  [4/5] docs/04_설치_안내.txt → 설치 첫 화면용 RTF(코드 페이지 949) 생성
  [5/5] wix build -culture ko-KR ... → Shield.msi, 마지막에 SHA-256 출력
cargo가 PATH에 없어도 %USERPROFILE%\.cargo\bin에 있으면 자동으로 사용합니다.
이전 Shield.msi는 먼저 지워 오래된 결과물을 성공 산출물로 오인하지 않게 합니다.
MSI 버전은 Cargo.toml을 따르므로, 버전을 올려 다시 빌드한 MSI를 설치하면 기존 설치가 업그레이드됩니다.
(같은 버전을 다시 설치해도 기존 설치를 교체합니다.)
성공하면 다음 파일을 기대합니다.

  target\release\shield.exe
  Shield.msi

필요하다면 빌드 전에 다음 점검도 수행하십시오.

  cargo fmt --check
  cargo test
  cargo build --release

테스트가 통과하더라도 GUI 동작, 파일시스템 안전성, 암호화 구현의 독립적 검증까지
완료되었다는 뜻은 아닙니다.

4. MSI에 포함되는 사용자 설명서
-------------------------------
installer.wxs는 docs/03_사용_방법.txt를 MSI에 포함합니다.
설치가 끝나면 사용 설명서가 Shield 설치 폴더의 "사용 방법.txt"로 배치됩니다.
또한 시작 메뉴의 Shield 폴더에 "Shield 사용 설명서" 바로가기가 생성되어
설치한 사람이 바로 열어 읽을 수 있습니다.

사용 설명서 파일이 없으면 WiX 빌드가 실패하므로 docs 폴더 구조를 유지하십시오.

5. 설치 후 확인
---------------
- Shield 앱이 실행되는가?
- 파일/폴더 선택 및 끌어 놓기가 동작하는가?
- 암호화/복호화 및 PIM/키 파일이 예상대로 동작하는가?
- 비밀번호 변경이 동작하는가?
- 설치 첫 화면에 주의사항/사용법이 보이고, 설치 진행률 화면이 표시되는가?
- 이전 버전 위에 설치했을 때 프로그램 목록에 Shield가 하나만 남는가(업그레이드)?
- 시작 메뉴의 "Shield" 바로가기로 앱이 실행되고, 작업 표시줄에 고정되는가?
- 시작 메뉴의 "Shield 사용 설명서" 바로가기가 열리는가?
- 설치 폴더에 "사용 방법.txt"가 존재하는가?
- 파일/폴더 우클릭 메뉴 및 .shd 복호화 메뉴가 등록되는가?
- MSI 제거 후 우클릭 메뉴와 시작 메뉴 바로가기가 제거되는가?

Windows 11에서는 클래식 셸 메뉴가 기본 우클릭 메뉴의 "더 많은 옵션 표시" 안에 나타날 수 있습니다.
우클릭 메뉴는 항목을 선택한 상태로 GUI를 열며, 암복호화를 자동 실행하지 않습니다.

6. 배포 전 권고
---------------
- 실제 중요 데이터가 아닌 테스트 복사본으로 암복호화 왕복을 확인하십시오.
- 비밀번호, PIM, 키 파일의 백업/복구 절차를 확인하십시오.
- MSI에 코드 서명을 적용할 수 있다면 서명하고 SHA-256 해시를 별도로 기록하십시오.
- 원본 파쇄는 되돌릴 수 없으며 SSD에서 물리적 완전 삭제를 보장하지 않습니다.
- 외부 보안 검토와 중단/전원 차단 테스트를 거친 후에 실제 중요 데이터에 적용하십시오.

참고: 이 문서는 빌드 절차와 설치 구성의 안내입니다. 현재 환경에서 MSI를 직접 빌드하거나
산출물의 실행 테스트를 완료했다는 뜻은 아닙니다.
