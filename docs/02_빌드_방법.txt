SHIELD 3.0.0 - 빌드 방법
========================
English: docs\en\02_build.txt

1. 폴더 구조
------------
Cargo.toml                워크스페이스(shield-platform, shield-core, shield-gui, shield-cli), 버전 3.0.0
crates\                   크레이트 4개 (01 문서 3절)
keys\release_key.asc      내장할 릴리스 공개키 (공개키만. 비밀키는 절대 저장소에 넣지 않음)
installer\windows\        installer.wxs, installer.ko-KR.wxl, installer.en-US.wxl
installer\linux\          .desktop, MIME, postinst/postrm, 파일 관리자 메뉴(filemanagers\)
build.ps1 / build.sh      Windows / Linux 빌드
.github\workflows\release.yml   GitHub Actions (Windows + Linux x86_64·aarch64, 태그로 릴리스)
.config\dotnet-tools.json WiX 5.0.2 고정
.cargo\config.toml        Windows(MSVC): C 런타임 정적 링크(vcruntime140.dll 불필요). RUSTFLAGS 환경 변수는
                          이 설정을 덮어쓰므로 쓰지 않습니다. 두 exe의 build.rs는 /DEPENDENTLOADFLAG:0x800
                          (가져오는 DLL을 System32에서만 찾음)을 넣습니다(보안 점검 2026-11-08, release_tests 확인)

2. 필요한 도구
--------------
공통      Rust stable 1.89 이상 (개발·시험: 1.99.1)
Windows   Visual Studio Build Tools(MSVC, rc.exe), .NET SDK 6+ (WiX 5 dotnet tool), 서명 시 Gpg4win, 선택 UPX
Linux     gcc, pkg-config, libgtk-3-dev, libxkbcommon-dev, libwayland-dev, libxcb-render0-dev,
          libxcb-shape0-dev, libxcb-xfixes0-dev, libgl1-mesa-dev (GUI), musl-tools와
          rustup target add <arch>-unknown-linux-musl (정적 콘솔), dpkg-dev (deb), python3 (소스 zip),
          선택: appimagetool (AppImage, APPIMAGETOOL=<경로>), rpmbuild (rpm), cargo-zigbuild + zig (--zig)
          서명 시 gnupg

3. 빌드 입력 (환경 변수 / 인수, 없으면 터미널에서 묻습니다)
----------------------------------------------------------
  저장소 URL     -RepoUrl / --repo / SHIELD_REPO_URL      https://github.com/<owner>/<repo>만 허용.
                 비우면 "개발 정보" 링크와 업데이트가 없는 빌드. build.rs도 형식을 다시 검사해 틀리면 빌드 중단.
  공개키 .asc    -PublicKeyPath / --pubkey / SHIELD_PUBKEY_PATH   기본 keys\release_key.asc.
                 프로그램에 내장되어 업데이트·무결성 검사에 쓰입니다. 비밀키 블록이 있으면 거부.
  서명 여부      -Sign|-NoSign / --sign|--no-sign / SHIELD_SIGN=y|n
  변형           -Variants msi,portable,console / --variants deb,appimage,console,rpm,zip / SHIELD_VARIANTS
  기타           -Culture ko-KR|en-US(MSI 언어), -MergeManifest / --merge-manifest(다른 OS 패키지 줄 합치기),
                 -GpgHome / --gpg-home, -SkipTests / --skip-tests, -UpxPath·-NoUpx, --zig, --arch x86_64|aarch64
비밀 정보: 서명 비밀번호는 인수·변수·로그 어디에도 들어가지 않고 gpg-agent(pinentry)가 묻습니다. 스크립트는
공개 값(URL, 지문, 파일 이름)만 출력합니다. bash는 set +x로 명령 추적을 끕니다.

4. Windows (build.ps1)
----------------------
  .\build.ps1                                    (모두 묻기)
  .\build.ps1 -RepoUrl https://github.com/o/r -NoSign -Variants msi,console
  .\build.ps1 -RepoUrl https://github.com/o/r -Sign -PublicKeyPath keys\release_key.asc
순서: 입력 검사 -> (서명 시) 공개키 하나만 든 임시 키링, 로컬 키링에 비밀키가 있는지 확인 -> cargo test
--workspace --release -> shield-gui.exe·shield.exe 빌드 -> 콘솔 전용 빌드(target\console) -> (서명 시)
두 exe 서명(.sig, 설치 폴더에 함께 들어가 무결성 검사에 쓰임) -> MSI -> 포터블 -> 소스 zip -> 릴리스 매니페스트 ->
(서명 시) 모든 배포 파일과 매니페스트 서명, 각 서명을 임시 키링으로 다시 검증 -> VERIFY.txt, SHA256SUMS.txt

5. Linux (build.sh)
-------------------
  ./build.sh --repo https://github.com/o/r --no-sign
  ./build.sh --repo https://github.com/o/r --sign --variants deb,appimage,console
  ./build.sh --zig --arch aarch64 --variants console     (정적 콘솔만 교차 빌드)
deb/AppImage/rpm은 이 컴퓨터의 아키텍처로만 만듭니다(GTK가 필요하므로). aarch64 패키지는 aarch64 컴퓨터나
GitHub의 ubuntu-24.04-arm 러너에서 만듭니다. 패키지 트리: /usr/bin/shield, /usr/bin/shield-gui,
/usr/share/applications(shield.desktop, shield-open.desktop), /usr/share/mime/packages/shield.xml,
/usr/share/icons/hicolor/*/apps/shield.png, /usr/share/nemo/actions, /usr/share/kio/servicemenus(KF6),
/usr/share/kservices5/ServiceMenus(KF5), /usr/share/shield(integrate.sh: 사용자별 Nautilus 스크립트·Thunar 동작),
/usr/share/doc/shield. 서명 시 /usr/bin/shield.sig·shield-gui.sig.

6. 산출물 (dist\)
-----------------
  Shield_v3.0.0_x64.msi                  Windows 설치 파일 (shield-gui.exe + shield.exe, PATH 추가)
  Shield_v3.0.0_x64_portable.exe         Windows 포터블 GUI
  shield-console_v3.0.0_windows_x64.exe  Windows 콘솔 전용 (GUI 의존성 없음)
  shield_v3.0.0_amd64.deb / _arm64.deb   Debian·Ubuntu 패키지
  Shield_v3.0.0_x86_64.AppImage / _aarch64.AppImage
  shield-console_v3.0.0_linux_x64 / _linux_arm64   musl 정적 콘솔
  shield_v3.0.0_x86_64.rpm               선택
  Shield_Project_v3_0_0.zip              소스 (target, dist, .git, 비밀키·.env 등 제외. 비밀키 블록이 보이면 중단)
  Shield_v3.0.0_release.txt              릴리스 매니페스트 (업데이트가 검사)
  각 파일의 .sig, 공개키 .asc, VERIFY.txt (서명 시), SHA256SUMS.txt (항상)
매니페스트 형식 (LF, 업데이트가 정확히 이 형식만 받습니다):
  Shield release manifest 1
  version 3.0.0
  sha256 <64자 소문자 16진수> <파일 이름>
업데이트는 매니페스트 서명 -> 버전(태그와 같고 현재보다 높아야 함) -> 패키지 SHA-256 -> 패키지 서명을 모두
확인합니다. Windows와 Linux를 따로 빌드했다면 한쪽 매니페스트를 -MergeManifest/--merge-manifest로 넘겨
한 매니페스트로 합친 뒤 서명하세요. GitHub 릴리스에는 업데이트용 파일 이름이 위 표와 같아야 합니다.

7. GitHub Actions (.github\workflows\release.yml)
------------------------------------------------
- windows(windows-latest), linux(ubuntu-24.04, ubuntu-24.04-arm) 작업이 빌드하고, vX.Y.Z 태그일 때 release
  작업이 매니페스트를 하나로 합쳐(모든 해시를 실제 파일과 대조) 서명한 뒤 gh release create로 올립니다.
- 시크릿 사용 방식 (서명 개인키는 절대 저장소에 넣지 않습니다):
  SHIELD_GPG_KEY         서명 부키만: gpg --armor --export-secret-subkeys <지문>!  (주 키 비밀키는 넣지 않음)
  SHIELD_GPG_PASSPHRASE  그 비밀번호
  각 작업은 RUNNER_TEMP 아래 임시 GNUPGHOME에 가져오고, 비밀번호는 그 폴더의 0600 파일로만 gpg에 전달하며,
  작업 끝에 폴더를 지웁니다. 시크릿 값은 echo하지 않습니다(GitHub도 로그에서 가립니다).
  시크릿이 없으면 서명 없이 빌드합니다(이 경우 업데이트가 그 릴리스를 거부합니다).
- AppImage: 저장소 변수 APPIMAGETOOL_URL과 APPIMAGETOOL_SHA256을 둘 다 정하면 그 파일을 받아 해시를 확인한 뒤
  씁니다. 고정되지 않은 도구는 받지 않습니다.
- 권장: 태그 보호 규칙, 릴리스 작업에 environment 승인, 부키 만료일 설정.

8. OS별 확인 목록
-----------------
Windows (설치 후)
  [ ] 시작 메뉴 Shield / Shield 파일 관리자 / 사용 설명서, 새 명령 창에서 shield version
  [ ] 탐색기에서 파일 여러 개 + 폴더 선택 -> Shield로 암호화 -> 창 하나, "하나로 묶기 / 각각 따로" 질문
  [ ] .shd 우클릭 복호화·열기, 설정 > 업데이트 > 프로그램 무결성 검사(서명 빌드면 "무결성 확인")
  [ ] 원본 파쇄: VSS 경고 표시, 3/7회 선택, 끝에 TRIM 결과(관리자 아니면 UAC)
  [ ] 제거 후 PATH·우클릭 메뉴가 사라지는지
  [ ] 2.1.0(한국어·영어 MSI 각각)이 설치된 상태에서 3.0.0 설치 -> 프로그램 목록에 Shield 하나, 우클릭 메뉴 하나,
      PATH에 설치 폴더 한 번 (05_테스트_및_점검_기록.txt 8.4 표)
  [ ] 창을 옮기고 닫은 뒤 다시 열면 같은 위치, 모니터를 뺀 뒤에는 화면 안에서 열림
Linux (deb 설치 후, GNOME·KDE·Xfce 등)
  [ ] 앱 메뉴 Shield, 터미널 shield version, .shd 두 번 클릭 -> 연결 프로그램
  [ ] Nemo·Dolphin 메뉴, /usr/share/shield/integrate.sh 실행 후 Nautilus 스크립트·Thunar 동작
  [ ] btrfs/ZFS/LVM/Timeshift/Snapper 볼륨에서 스냅숏 경고, ext4 SSD에서 FITRIM(root가 아니면 pkexec 안내)
  [ ] Wayland와 X11에서 창 크기가 Windows와 같은지(1040x700 논리 크기, 글자 크기), Xft.dpi가 없는 X11과
      잘못된 WINIT_X11_SCALE_FACTOR로도 시작되는지
  [ ] 화면 캡처 방지 / 창 위치 기억(Wayland)이 "사용할 수 없어 해제됨(사유)"으로 보이는지
  [ ] AppImage: 실행, "Shield.AppImage cli version", 설정 > 업데이트 확인
공통
  [ ] Windows에서 만든 .shd를 Linux에서 열고 반대로도 (자동 테스트가 있지만 실제 파일로도)
  [ ] shield verify <파일> <파일>.sig --key <공개키>로 배포 파일 검증
