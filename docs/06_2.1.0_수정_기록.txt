SHIELD 2.1.0 - 수정 기록
========================

작성일: 2026-11-02   갱신: 2026-11-02 (8절 (4)~(7) 추가)
대상: Shield 2.0.0 → 2.1.0 (요구 명세: SHIELD 2.1.0 수정 프롬프트 + "UPX 경로를 주면 포터블 버전도 빌드")

1. 현재 상태 요약
-----------------
- cargo build: 성공 (경고 0개)
- cargo test: 104개 모두 통과 (실패 0개, 약 5분)
- cargo clippy --all-targets: 경고 0개
- 모든 소스 파일 500줄 미만
- 암호 설계(XChaCha20-Poly1305, Argon2id, KEK/DEK 분리, 인증된 메타데이터, 7z(LZMA2/Zstd),
  7회 파쇄, SecTemp)는 바꾸지 않았습니다. 형식 버전은 암호화된 메타데이터 안에만 있습니다.
- 이전 형식과의 하위 호환은 두지 않았습니다.

2. 마무리 단계에서 찾아 고친 문제
----------------------------------
(1) B-12가 실제로는 빠져 있었음
    sectemp.rs에 블록 표 상한과 try_reserve가 없었습니다. 둘 다 넣었습니다.
    이제 메모리 확보에 실패하면 프로그램이 죽지 않고 오류를 돌려줍니다.

(2) 숨은 스트림(ADS) 검사 오류
    파일의 본래 내용(기본 스트림 "::$DATA")까지 숨은 스트림으로 셌습니다.
    그래서 원본 파쇄를 켜고 암호화하면 항상 "숨은 스트림 발견"으로 멈췄습니다. (ads.rs)

(3) 스트림을 함께 파쇄하면 원본이 남음
    스트림을 덮어쓰면 파일의 수정 시각이 바뀌어서, 바로 뒤의 "그대로인가?" 검사가
    원본을 "바뀐 파일"로 보고 남겨 두었습니다.
    이제 파일 확인을 먼저 하고 그 다음에 스트림을 덮어씁니다. (wipe.rs, manifest.rs)

(4) 파쇄 실패를 성공으로 표시
    파쇄·여유 공간 덮어쓰기·TRIM이 실패해도 결과가 성공(초록색)이었습니다.
    이제 오류(빨간색)로 알립니다. 결과 .shd 파일은 그대로 남습니다. (engine.rs, container.rs)

(5) 명세에 없던 기능 추가
    파일 관리자에 "선택 항목 삭제"를 넣었습니다. 설정에 "삭제 전에 확인"이 있는데
    정작 삭제 기능이 없었기 때문입니다. 삭제도 전체를 다시 암호화·검증한 뒤 교체합니다.

  - 창이 좁아지면 이름 열이 먼저 줄고 "…"로 잘림, 마우스를 올리면 전체 이름

  - 압축률 검사를 항상 적용 (64 MiB부터)
  - 풀다가 인증된 전체 크기를 넘으면 그 자리에서 중단

B-4 Shield가 만든 폴더 지우기

5. 잠금을 이렇게 만든 이유 (B-2)
--------------------------------
- .shd 파일 자체가 아니라 별도 잠금 파일을 잠급니다.
  비밀번호 변경·항목 추가는 .shd를 원자적으로 통째로 바꾸는데,
  .shd 자체를 잠그면 바꿀 때 잠금이 풀리거나 교체가 막히기 때문입니다.
- 잠금 파일 이름은 정규화한 경로의 해시 → 같은 파일을 다른 표기로 열어도 같은 잠금
- LockFileEx: 프로그램이 비정상 종료해도 OS가 잠금을 풀어 주므로 "영원히 잠긴" 상태가 생기지 않음
- 키 유도(오래 걸림)보다 잠금을 먼저 잡아서, 어차피 못 할 작업에 시간을 쓰지 않음
- 잠금을 잡고 있는 동안에는 잠금 파일을 지울 수 없게 열어 둠

8. 추가 수정 (2026-11-02, 사용자 요청)
---------------------------------------
(1) build.ps1 - UPX 경로 입력
    - .\build.ps1 만 실행해도 "UPX 경로"를 묻습니다. 경로를 넣으면 빌드한 shield.exe를
      UPX로 압축해 dist\Shield_v{버전}_portable.exe를 만들고, 그냥 Enter를 치면 건너뜁니다.
    - upx.exe 파일 경로, upx.exe가 든 폴더 경로 둘 다 됩니다.
      창에 파일을 끌어 놓을 때 붙는 따옴표와 "& "도 알아서 지웁니다.
    - -UpxPath "경로"로 미리 주면 묻지 않습니다. -NoUpx를 주면 묻지 않고 건너뜁니다.
    - 입력이 자동으로 들어오는 환경(입력 리디렉션)에서는 묻지 않습니다.
    - 압축 뒤 upx -t 무결성 검사와 ASLR/DEP 플래그 확인은 예전과 같습니다.
    - 이 PC에는 upx.exe가 없어서 실제 압축은 실행해 보지 못했습니다.
      스크립트 문법 검사와 경로 처리(파일, 폴더, 따옴표, "& ") 시험만 했습니다.

      1040×700으로 맞춰야 합니다. 이 변경 뒤 테스트는 아직 다시 돌리지 않았습니다.

(5) 마우스 엔트로피 막대 (ui.rs, ui::mouse_meter만 변경)
    - 수집이 100%가 되면 막대가 초록색(테마의 "성공" 색)으로 바뀝니다. 그 전에는 강조색입니다.
    - 수집된 샘플 수가 항상 화면에 보입니다. 암호화·키 교체 탭에서는 "샘플 수 · 마우스 움직임 안내" 한 줄이고,
      100%가 되면 안내는 빼고 샘플 수만 남습니다. 설정 > 보안의 막대도 같은 함수라 함께 바뀝니다.
    - 새 번역 문구는 만들지 않고 기존 문구(set.mouse_count)를 썼습니다. 이 변경은 컴파일해 보지 못했습니다.
    - A-3 원칙은 그대로입니다. 보여 주기만 하고 어떤 버튼도 이것을 기다리지 않습니다.

(6) 테스트 출력 참고
    - main.rs 첫 줄의 windows_subsystem = "windows"(release 전용) 때문에 cargo test --release의 실행 파일은
      콘솔에 출력을 내지 않습니다. 약 5분 걸리는 동안 아무 출력이 없어 멈춘 것처럼 보일 수 있습니다.
      출력을 보려면 `cargo test --release -- --test-threads=1 --nocapture *> test_out.txt`를 쓰세요.
    - 코드는 바꾸지 않았습니다. 첫 줄을 not(test)까지 포함하도록 바꾸면 해결되지만 적용하지 않았습니다.

      빌드 단계, 창 크기, 마우스 막대). 05는 2.0 기록을 그대로 두고 9절에 2.1.0 갱신을 덧붙였습니다.
